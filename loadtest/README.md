# 부하 테스트 (k6)

동시 접속 1,000명 목표를 검증하는 시나리오입니다. [k6](https://grafana.com/docs/k6/latest/set-up/install-k6/)는 무료이며 설치 없이 실행 파일만 받아도 됩니다.

## 시나리오 (`kufim-load.js`, 약 3분)

| 이름 | 동시 사용자 | 행동 |
|---|---|---|
| browse | 690 | 홈 첫 화면 6개 요청 → 부스 상세 → 인기 부스, 5~13초 간격 |
| waiting | 300 | 인기 부스 3곳(boothId 1~3)에 접수 → 10초마다 내 대기표·대기 현황 조회(웹소켓이 끊긴 최악의 경우) |
| admin | 10 | 로그인 후 인기 부스 대기 명단을 5초마다 새로고침 |

이용자마다 다른 `X-Client-Token`과 `X-Forwarded-For`를 보내 서로 다른 휴대폰처럼 동작합니다. `X-Forwarded-For`는 `mysql` 프로필에서 사설망(로컬·도커)에서 들어온 요청일 때만 반영됩니다.

통과 기준: 실패율 1% 미만, 전체 p95 500ms 미만, 내 대기표 p95 300ms 미만, 관리자 명단 p95 500ms 미만.

## 실행

1. 운영과 같은 `mysql` 프로필로 백엔드를 띄우고, 축제·무대·**웨이팅 부스 20개**(ID 1~3이 인기 부스)·공지·공연을 넣습니다.
2. 실행:

```bash
k6 run -e BASE_URL=http://127.0.0.1:8080 -e ADMIN_LOGIN=admin -e ADMIN_PASSWORD='관리자-비밀번호' loadtest/kufim-load.js
# 규모를 줄이려면 -e SCALE=0.1 (1/10)
```

비밀번호는 명령줄 환경 변수로만 넘기고 파일에 적지 않습니다.

## 결과 기록 (로컬 PC, MySQL 8.0.46 · Redis · `mysql` 프로필 jar, 2026-10-11)

동일 시나리오, 약 97,800요청, 실패 0건.

| 지표 (p95) | 최적화 전 | 최적화 후 |
|---|---|---|
| 전체 응답 | 22.7ms | 2.6ms |
| 관리자 대기 명단 (부스당 약 100팀) | 81ms | 10ms |
| 내 대기표 | 3.3ms | 2.5ms |

최적화 내용: 순번 계산을 `count` 쿼리로, 관리자 명단 순번을 한 번 훑기로, 부스 목록 대기 수·지도 핀과 공지 읽음 여부를 일괄 조회로 변경.

> 로컬 PC 한 대에서 k6·백엔드·DB를 함께 돌린 결과입니다. 배포 직후 실제 서버(EC2)에 `SCALE=0.1`부터 짧게 다시 확인합니다. 운영 서버에 돌린 뒤에는 테스트 대기표가 남으므로 정리합니다.
