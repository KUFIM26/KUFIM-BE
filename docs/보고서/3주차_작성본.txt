2. 프로젝트 주차 진행 내용
화면을 그리기 전에 디자인 토큰을 먼저 정의했습니다. 색상, 타이포그래피, 간격을 토큰으로 묶고 Figma 시안과 프론트엔드 코드가 같은 토큰만 참조하게 해, 시안의 변경이 구현에 그대로 이어지도록 했습니다.
색상은 축제가 주간 직사광과 야간 옥외에서 모두 쓰인다는 점을 고려해 고대비 라이트 테마 단일로 정했습니다. 어두운 테마는 직사광 아래에서 오히려 읽기 어렵기 때문입니다. 대기 순번처럼 걸으면서 힐끗 보는 정보는 본문과 분리해 별도의 큰 글자 크기를 두었습니다.
혼잡도는 색상에 등급명과 칸 게이지를 항상 함께 표시하고 추정 인원 숫자를 병기해, 색상만으로 정보를 전달하지 않도록 했습니다.
Figma 시안은 이용자 모바일 화면과 부스 운영자 화면으로 나눠 설계했고, 완성된 시안을 2주차 기능 정의서와 화면 단위로 대조했습니다. 이때 앱 내 QR 스캐너는 빼고 기본 카메라로 QR을 읽어 바로 접속하는 방식으로 정했습니다. 이용 단계가 적고 별도 권한 요청이 없기 때문입니다.


3. 프로젝트 주차 진행 결과
디자인 토큰을 확정하고 코드에서 바로 쓸 수 있는 CSS 파일로 작성했습니다.
이용자 화면 프로토타입을 완성했습니다. 홈, 무대 타임테이블과 공연 상세, 축제 지도와 부스 리스트, QR 웨이팅 접수와 내 대기표, 공지와 알림함으로 구성됩니다.
부스 운영자 화면 프로토타입을 완성했습니다. 대기 명단에서 호출, 전화, 취소를 처리하고 운영 상태와 예상 대기시간을 설정하는 흐름입니다.
시안을 기준으로 기능 정의서를 개정했습니다. 시안에 새로 생긴 알림함, 부스 운영 상태, 날짜 종료 시 대기표 만료를 반영했습니다.
지도교수님 미팅에서 받은 피드백을 반영해 프로토타입을 확정했습니다.
김도현: Figma 기반 이용자, 부스 운영자 화면 설계, 야간 시인성 고려 색상, 타이포그래피 설정, QR 웨이팅 사용자 플로우 설계, 축제 지도 화면 설계, 지도교수님 피드백 반영
정근녕: 부스 운영자 화면 흐름 검토, 백엔드 연동 관점 UI 데이터 구조 검증, API 응답 구조와 화면 설계 정합성 확인


4. 기타(문제점, 해결방법, 자기평가 등)
관례적인 혼잡도 배색을 사용해도 실제로 글들이 제대로 읽히지 않았습니다. '보통' 단계의 노란 배경은 흰 글씨로 명도 대비 기준을 만족할 수 없고 흰 페이지와도 구분되지 않아, 어두운 글씨와 테두리를 적용했습니다. 또 색각 이상 조건에서는 '혼잡'과 '매우 혼잡'이 색만으로 구분되지 않는 문제들이 생기기도 해서 조정하여 프로토타입 및 UI를 작성했습니다.
이번 주차는 대비, 글자 크기, 터치 영역 등 기본 접근성까지만 반영했고, 다크 모드 등 추가 접근성은 2차 기능 재설계 단계에서 진행하겠습니다.
계획서의 관리자 혼잡도 입력, 긴급 공지 화면은 부스 운영자의 대기 호출 흐름을 우선 설계하면서 총괄 관리자 화면으로 묶어 후속 설계로 넘겼습니다. 5주차 혼잡도 관제 구현 전에 보완하겠습니다.
