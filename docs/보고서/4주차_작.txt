목표	
● 개발 환경 구축

● 프론트엔드와 백엔드 GitHub 레포지토리 분리 및 기본 개발 규칙 설정

● React 및 Spring Boot 기반 초기 프로젝트 구조 구성

● AWS 배포 환경 구조 설계 및 기본 인프라 구성

● GitHub Actions 기반 CI/CD 파이프라인 초안 설정
진행내용	
3주차에 확정한 Figma 프로토타입과 기능 정의서를 구현 기준으로 삼아 개발 환경을 구축했습니다. 학생 이용자용 모바일 웹과 운영진용 관리자 페이지를 하나의 서비스 흐름으로 연결하되, 프론트엔드와 백엔드의 역할을 명확히 분리하기 위해 각각 별도의 GitHub 레포지토리를 구성했습니다.
프론트엔드는 React 기반으로 초기 프로젝트를 구성하고, 3주차에 정리한 디자인 토큰을 CSS 변수 형태로 적용했습니다. 이를 통해 이후 화면을 구현할 때 색상, 글자 크기, 간격 등 UI 기준을 일관되게 사용할 수 있도록 했습니다. 또한 학생용 모바일 화면을 우선 기준으로 반응형 레이아웃의 기본 구조를 마련했습니다.
백엔드는 Spring Boot 기반으로 프로젝트를 생성하고, 향후 축제 정보·공연 타임테이블·부스·웨이팅·공지 기능을 확장할 수 있도록 계층형 구조를 설계했습니다. 프론트엔드와의 연동을 고려하여 API 응답 형식, 오류 응답 방식, 환경 변수 관리 원칙을 함께 정리했습니다.
진행결과	
프론트엔드와 백엔드 GitHub 레포지토리를 분리하여 생성하고, 팀원별 작업 브랜치와 병합 방식 등 협업 규칙을 정했습니다.
프론트엔드는 React 기반 초기 프로젝트를 구성하고 디자인 토큰을 적용했습니다. 공통 레이아웃, 라우팅 구조, 모바일 환경을 고려한 기본 스타일을 마련하여 이후 프로그램 안내, 축제 지도, QR 웨이팅 화면을 순차적으로 구현할 수 있는 기반을 갖췄습니다.
백엔드는 Spring Boot 초기 프로젝트와 기본 패키지 구조를 구성했습니다. 향후 API 구현 시 일관성을 유지할 수 있도록 공통 응답 형식과 예외 처리 방향을 정리했으며, 프론트엔드 연동을 위한 기본 설정을 완료했습니다.
AWS 배포 환경의 구성 방향을 정리하고, 서비스 코드의 빌드와 배포 과정을 자동화하기 위한 CI/CD 파이프라인 초안을 설정했습니다. 이를 통해 다음 주차부터 구현되는 기능을 개발 서버에서 빠르게 확인하고 수정할 수 있는 기반을 마련했습니다.
기타
(문제점, 해결방법,
자기평가 등)	
프론트엔드와 백엔드를 동시에 초기 구성하는 과정에서 개발 환경과 배포 환경의 설정값이 섞일 수 있는 문제가 있었습니다. 이를 줄이기 위해 민감한 설정값은 코드에 직접 작성하지 않고 환경 변수로 분리하는 방향을 정했습니다. 또한 로컬 개발 환경과 배포 환경에서 동일한 방식으로 동작하도록 설정 파일과 실행 절차를 문서화했습니다.
초기에는 빠른 기능 구현을 위해 화면 작업을 우선 진행할 수도 있었지만, 실제 축제 서비스는 짧은 기간에 많은 사용자가 접속할 가능성이 있어 개발 및 배포 기반을 먼저 안정화하는 것이 필요하다고 판단했습니다. 이번 주차에 구축한 프로젝트 구조와 협업·배포 환경을 바탕으로 다음 주차부터는 프로그램 안내와 메인무대 관제 기능 구현에 집중하겠습니다.
