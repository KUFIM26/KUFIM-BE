# KUFIM 기능 정의서


| 항목 | 내용 |
|---|---|
| 문서 버전 | v0.4 |
| 수정 기준 | 기존 기능정의서 v0.3 + Figma KUFIM UI |
| 수정 방향 | 현재 Figma에 구현된 모바일 UI 흐름을 기준으로 화면/기능 범위를 현실화 |
| 주요 변경 | QR 앱 내 스캐너 제외, 비회원 익명 토큰 웨이팅 유지, 사용자 모바일 화면 중심 재정리, 관리자 범위 MVP화 |

---

## 1. 개요

본 문서는 KUFIM 서비스의 기능 요구사항을 실제 Figma UI 구성에 맞춰 재정의한다.

기존 기능정의서 v0.3은 전체 운영 시스템을 넓게 정의하고 있으나, 현재 Figma는 사용자 모바일 웹과 부스 관리자 중심으로 설계되어 있다. 따라서 본 v0.4에서는 다음 원칙을 적용한다.

- 현재 Figma에 존재하는 화면을 우선 기준으로 삼는다.
- 앱 내 QR 스캐너는 구현하지 않는다.
- 웨이팅은 로그인 없이 익명 토큰 기반으로 동작한다.
- 전화번호는 선택 입력이며, 호출 문자 발송 목적에만 사용한다.
- 관리자 기능은 1차 MVP에서 부스 운영자 중심으로 축소하고, 총괄 관리자 기능은 후속 확장으로 둔다.

## 6. 상태 및 코드 정의

### 6.1 웨이팅 상태

```text
WAITING -> CALLED -> ENTERED
   |          |
   v          v
CANCELED   NO_SHOW
```

| 상태 | 설명 | 전이 주체 |
|---|---|---|
| `WAITING` | 순번 부여 완료, 호출 대기 | 시스템 |
| `CALLED` | 운영자가 호출, 유예 시간 진행 중 | 운영자 |
| `ENTERED` | 부스 입장 완료 | 운영자 |
| `CANCELED` | 이용자 또는 운영자 취소 | 이용자/운영자 |
| `NO_SHOW` | 호출 후 미응답 확정 | 운영자 |
| `EXPIRED` | 운영 종료 또는 날짜 종료로 만료 | 시스템 |

> `WAITING`, `CALLED`는 활성 상태이며 동일 부스 중복 등록 차단 기준으로 사용한다.

### 6.2 부스 운영 상태

| 상태 | 설명 |
|---|---|
| `OPEN` | 운영 중, 신규 웨이팅 가능 |
| `PAUSED` | 대기 마감, 신규 웨이팅 불가 |
| `CLOSED` | 운영 종료 |

### 6.3 부스 분류

현재 Figma UI의 필터 기준을 우선 반영한다.

| 코드 | 명칭 |
|---|---|
| `ALL` | 전체 |
| `STUDENT_COUNCIL` | 총학생회 |
| `COLLEGE` | 단과대학 |
| `CLUB` | 동아리 |
| `INDIVIDUAL` | 개인 |
| `UNIVERSITY` | 학교 본부 |

> 기존 기능정의서의 음식, 체험, 푸드트럭, 홍보, 공연·전시 분류는 부스 상세의 운영 콘텐츠 태그로 병행 사용할 수 있다.

## 7. 주요 사용자 플로우

### 7.1 QR 웨이팅 플로우

1. 사용자가 부스 앞 QR을 스마트폰 기본 카메라로 스캔한다.
2. 브라우저가 `U-08 부스 상세/웨이팅 등록` 화면으로 이동한다.
3. 화면에 부스명, 위치, 운영시간, 대기 팀 수, 예상 대기시간을 표시한다.
4. 사용자가 인원 수를 선택한다.
5. 전화번호 입력은 선택 사항으로 제공한다.
6. 전화번호 입력 시 개인정보 안내를 표시한다.
7. 사용자가 웨이팅을 등록한다.
8. 시스템이 익명 토큰 기준으로 동일 부스 활성 웨이팅 여부를 확인한다.
9. 중복이 아니면 대기번호와 순번을 발급한다.
10. 사용자는 `U-06 내 대기표` 화면에서 순번과 남은 시간을 확인한다.
11. 호출 시 화면 상태가 전환되고 알림함에 호출 알림이 표시된다.
12. 전화번호가 있으면 호출 문자를 발송한다.
13. 부스 운영자가 입장 완료 또는 노쇼를 처리한다.

### 7.2 토큰 소실 대응 플로우

1. 사용자가 브라우저 데이터를 삭제하거나 다른 브라우저로 접속한다.
2. 기존 익명 토큰을 찾을 수 없어 자동 대기표 복원이 실패한다.
3. 사용자는 캡처해둔 대기번호를 부스 운영자에게 제시한다.
4. 운영자는 대기번호로 대기표를 조회한다.
5. 운영자는 현장 확인 후 입장 완료, 취소, 재안내를 처리한다.

### 7.3 부스 운영자 호출 플로우

1. 부스 운영자가 `A-01 부스 운영 대시보드`에 접속한다.
2. 대기 명단에서 다음 대기 팀을 확인한다.
3. 운영자가 호출하기를 누른다.
4. 사용자 대기표 상태가 `CALLED`로 변경된다.
5. 전화번호 입력자에게 문자를 발송한다.
6. 사용자가 도착하면 운영자가 입장 완료 처리한다.
7. 기준 시간이 지나도 도착하지 않으면 노쇼 후보로 표시하고 운영자가 확정한다.
