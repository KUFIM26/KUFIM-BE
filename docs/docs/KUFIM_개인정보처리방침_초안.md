# KUFIM 개인정보 처리방침 (초안)

> 요구사항 COM-010(고지·조건부 동의), NFR-S-005(최소 수집), NFR-S-006(파기) 대응

| 항목 | 내용 |
|---|---|
| 문서 버전 | v0.3 |
| 작성일 | 2026-08-31 (개정 2026-09-01) |
| 상태 | **방침 확정 — 전화번호 선택 수집** |
| 남은 확인 | 학교 개인정보 담당 부서 문의 (배포 전 권장) |

---

## 0. 핵심

**KUFIM은 전화번호를 선택 입력으로만 수집한다.**

- 번호를 입력하면 → 호출 시 **문자메시지**를 받는다
- 번호를 입력하지 않으면 → **화면 표시**로만 순서를 확인한다 (등록에 아무 제약 없음)

이름, 학번, 이메일은 받지 않는다. 수집하는 개인정보는 **전화번호 하나뿐**이다.

2026-09-01에 이렇게 결정했다. 계획서에 명시된 "입장 순서 문자메시지 발송"을 구현하되,
번호를 강제하지 않아 개인정보 최소 수집 원칙(NFR-S-005)을 함께 지키기 위함이다.

---

## 1. 수집 항목

### 1.1 이용자로부터 수집하는 것

| 항목 | 필수 여부 | 수집 목적 | 보유 기간 |
|---|---|---|---|
| 휴대전화번호 | **선택** | 웨이팅 호출 안내 문자 발송 | 축제 종료 후 **7일 이내 파기** |

동의를 거부해도 웨이팅 등록에는 아무 제약이 없다. 화면 표시로 순서를 확인하면 된다.

### 1.2 서비스 이용 과정에서 생성·기록되는 것

| 항목 | 성격 | 개인정보 해당 |
|---|---|---|
| 익명 토큰 (UUID) | 브라우저가 생성. 웨이팅 소유권 판별용 | **아님** — 개인을 식별할 수 없음 |
| 웨이팅 기록 (부스, 인원 수, 시각) | 익명 토큰에 연결 | 아님 |
| 문자 발송 이력 | **전화번호를 저장하지 않는다.** 발송 결과·시각만 기록 | 아님 |
| 접속 로그 (IP, User-Agent) | 서버 자동 기록 | **해당** |
| 관리자 조작 이력 | 운영진 대상 | **해당** (운영진에 한함) |

> **문자 발송 이력에 전화번호를 중복 보관하지 않는다.** 번호가 필요하면 웨이팅 기록과 조인한다.
> 이렇게 두면 웨이팅의 전화번호 하나만 파기해도 개인정보가 전부 사라진다.

---

## 2. 동의 절차

전화번호를 **입력하는 경우에만** 아래 동의 문구를 노출한다. 미입력자에게는 표시하지 않는다.

> ### 개인정보 수집 및 이용 동의 (선택)
>
> - **수집 항목**: 휴대전화번호
> - **수집 목적**: 웨이팅 호출 안내 문자 발송
> - **보유 기간**: 축제 종료 후 7일 이내 파기
> - 동의하지 않으셔도 웨이팅 등록이 가능하며, 대기표 화면에서 순서를 확인하실 수 있습니다.
>
> ☐ 위 내용에 동의하고 문자 안내를 받겠습니다.

**서버는 이 규칙을 강제한다.** 전화번호가 있는데 동의가 없으면 등록을 `400 C002`로 거부한다(F-COM-08).

## 3. 보유 및 파기

| 데이터 | 보유 기간 | 파기 방법 |
|---|---|---|
| **휴대전화번호** | 축제 종료 후 **7일 이내** | 관리자 화면에서 일괄 파기, 결과를 `privacy_purge_log`에 기록 |
| 접속 로그 (IP 포함) | 축제 종료 후 30일 | 자동 삭제 |
| 익명 토큰 | 축제 종료 후 30일 | 일괄 제거 |
| 웨이팅 이용 기록 | 분석 보고서 완료 시까지 (최대 90일) | 개인 식별자 제거 후 통계만 보존 |
| 문자 발송 이력 | 비용 정산·분석 완료 시까지 | 전화번호가 없으므로 파기 대상 아님 |

파기는 관리자 화면(A-16)에서 수행한다. 15주차 "개인정보 데이터 파기" 산출물의 증빙이 된다.

## 4. 보호 조치

| 조치 | 내용 |
|---|---|
| 전송 구간 암호화 | 전 구간 HTTPS/WSS (NFR-S-001) |
| 화면 표시 | 관리자 화면에서도 **항상 마스킹** (`010-****-5678`) (NFR-S-005) |
| 접근 통제 | 담당 부스 운영자만 조회 가능 (NFR-S-003) |
| 조회·파기 이력 | `audit_log`에 수행자·시각 기록 (F-ADM-07) |
| 저장 | 별도 암호화 저장 여부는 4주차에 결정 |

## 5. 이용자 안내 문구 (서비스 내 게재)

> ### KUFIM 이용 안내
>
> 이 서비스는 **회원가입 없이** 이용할 수 있습니다.
> 웨이팅 등록 시 필요한 것은 인원 수뿐이며, **전화번호는 선택 입력**입니다.
>
> 번호를 입력하시면 차례가 되었을 때 **문자로 안내**드립니다.
> 입력하지 않으셔도 대기표 화면에서 순서를 실시간으로 확인하실 수 있습니다.
>
> 대기표는 이용하시는 브라우저에 저장된 임의의 식별값으로 표시됩니다.
> **브라우저 데이터를 삭제하거나 다른 기기로 접속하면 대기표를 다시 불러올 수 없습니다.**
> 등록 시 안내되는 **대기 번호를 기억하거나 화면을 캡처해 두시면** 부스 운영자가 확인해 드릴 수 있습니다.
>
> 입력하신 전화번호는 축제 종료 후 7일 이내에 파기됩니다.
> 서버 접속 기록(IP 주소)은 서비스 안정성 확인을 위해 30일간 보관 후 삭제됩니다.
>
> 문의: 축제 상황실

## 6. 제3자 제공 및 위탁

### 6.1 제3자 제공
개인정보를 제3자에게 제공하지 않는다.

### 6.2 처리 위탁

| 수탁자 | 위탁 업무 | 비고 |
|---|---|---|
| Amazon Web Services | 서버·저장소 운영 | 리전 ap-northeast-2 (서울) |
| 문자 발송 사업자 | 호출 안내 문자 발송 | **사업자 미정 (TBD-07).** 선정 후 이 표에 명시하고 안내 문구에 반영한다 |

- **카카오맵 SDK**는 브라우저에서 직접 호출되며 위치 좌표가 서버로 전송되지 않는다.
- **번역 API**(TBD-05)에는 개인정보를 전달하지 않는다. 번역 대상은 부스명·공연 정보뿐이다.

> **문자 발송 사업자 선정 전에는 이 방침을 공개 게재할 수 없다.** 수탁자를 명시해야 하기 때문이다. TBD-07을 6주차 전에 확정해야 하는 이유 중 하나다.

---

## 7. 이용자 권리

- 웨이팅 등록은 언제든 취소할 수 있다(F-WAI-11).
- 입력한 전화번호의 열람·정정·삭제를 원하면 축제 상황실로 문의한다.
- 문자 수신을 원하지 않으면 애초에 번호를 입력하지 않으면 된다.
