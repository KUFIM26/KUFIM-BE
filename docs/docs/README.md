## 문서 관계

```
요구사항 명세서 (UC → FR / NFR)
        │
        ├──> 기능 정의서 (F-ID · 화면 · 상태)
        │        │
        │        ├──> openapi/kufim-openapi.yaml  ← API 원본
        │        │         ├──> KUFIM_API_상세참조.md   (자동 생성)
        │        │         └──> openapi/kufim-api.d.ts  (자동 생성)
        │        ├──> ERD ──────────> sql/schema.sql
        │        └──> 디자인 토큰 ───> design/tokens.css
        │
        └──> 기술 스택 정의서 ──> 시스템 아키텍처 ──> loadtest/*.js
```

> **API는 OpenAPI YAML이 원본이다.** 마크다운 상세 참조와 TypeScript 타입은 생성물이므로 직접 수정하지 않는다.
> 갱신 절차는 [INIT_SESSION §4.2](./INIT_SESSION.md)를 참조한다.

문서 간 추적성은 ID로 연결된다.

```
요구사항  WAI-005  "이용자는 인원 수를 입력하고 웨이팅을 등록한다"
   ↓
기능      F-WAI-05 · 화면 U-07 · 담당 공통 · 우선순위 M
   ↓
API       POST /booths/{boothId}/waitings
   ↓
데이터    waiting 테이블 + Redis waiting:queue:{boothId}
```

## 확정된 개발 범위

**구현 대상**

| 계획서 | 기능 | 단계 |
|---|---|---|
| A | 프로그램 안내 및 메인무대 관제 | 1단계 |
| B | 스마트 웨이팅 (QR) | 1단계 |
| C | 축제 지도 | 1단계 |
| D | 관리자 대시보드 | 1단계 |
| J | 외국어(영어) 지원 | 2단계 |

**보류** — E(신고 제도) · F(스탬프 투어) · G(굿즈 구매) · H(티켓팅·추첨) · I(분실물) · 멀티 이벤트 · 접근성 강화

**문자 발송 구현 확정 (2026-09-01)** — 전화번호를 **선택 입력**으로 받아 입력자에게만 호출 문자를 발송한다. 미입력자는 화면 표시로만 안내한다.

**발송 비용은 팀 자비 부담** — 일일 한도와 건당 1회 제한으로 폭주를 차단하고, 한도 초과 시 문자만 중단하고 화면 표시는 계속 동작한다.
