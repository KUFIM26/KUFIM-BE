## 1. 개요

요구사항 명세서의 기능 요구사항(FR)을 **구현 단위 기능 / 화면 / 상태**로 분해한다.
본 문서의 기능 ID는 API 명세서와 1:1 대응되며, 개발 진행률 추적의 기준이 된다.

**표기**
- 우선순위 `M`(필수) / `S`(권장) / `C`(선택)
- 담당 `FE`(김도현) / `BE`(정근녕) / `공통`

## 2. 정보 구조 (IA)

### 2.1 User Web — 이용자 화면

| 화면 ID | 화면명 | 진입 경로 | 주요 기능 |
|---|---|---|---|
| U-01 | 홈 | 루트, QR 외 진입 | 긴급 공지, 현재/다음 공연, 무대 혼잡도 요약, 빠른 이동 |
| U-02 | 타임테이블 | 하단 탭 → 프로그램 | 일자·무대별 공연 시간표 |
| U-03 | 라인업 | 프로그램 탭 내 전환 | 초청 가수 / 학생 공연 출연진 |
| U-04 | 공연 상세 | U-02, U-03 | 공연 정보, 무대 위치 바로가기 |
| U-05 | 부스 목록 | 하단 탭 → 부스 | 카테고리 필터, 검색, 대기 팀 수 |
| U-06 | 부스 상세 | U-05, U-10 | 소개·운영시간·이미지, 대기 현황, 웨이팅 진입 |
| U-07 | 웨이팅 등록 | U-06, **QR 스캔** | 인원 수 입력, 등록 |
| U-08 | 내 대기표 | U-07 완료 후, U-09 | 순번·예상 대기시간 실시간, 호출 상태, 취소 |
| U-09 | 내 대기표 목록 | 하단 탭 → 내 대기 | 다중 웨이팅 조회 |
| U-10 | 축제 지도 | 하단 탭 → 지도 | 도면, 마커, 카테고리 필터, 현재 위치 |
| U-11 | 무대 현황 | U-01, 하단 탭 | 구역별 혼잡도 색상+숫자, 입장 통제 상태 |
| U-12 | 공지 | 배너 탭 | 공지 목록·상세 |
| U-13 | 설정 | 헤더 | 언어 전환(KO/EN), 알림 권한 안내 |
| U-14 | 오류/오프라인 | 전역 | 네트워크 오류·점검 안내 |

> **QR 진입 플로우**: QR 스캔은 스마트폰 기본 카메라 앱으로 수행한다. 앱 내 스캐너를 구현하지 않으며, QR은 `U-07`로 직접 연결되는 딥링크 URL을 담는다.

## 4. 상태 및 코드 정의

### 4.1 웨이팅 상태 전이

```
                 [등록]
                   |
                   v
             +----------+   운영자 호출    +----------+  입장 확인   +-----------+
             | WAITING  | --------------> |  CALLED  | -----------> |  ENTERED  |
             +----------+                 +----------+              +-----------+
                   |                           |
        이용자 취소 |                            | 5분 경과 후 운영자 확정
                   v                           v
             +-----------+               +-----------+
             | CANCELED  |               |  NO_SHOW  |
             +-----------+               +-----------+
```

| 상태 | 코드 | 설명 | 전이 주체 |
|---|---|---|---|
| 대기 중 | `WAITING` | 순번 부여 완료, 호출 대기 | — |
| 호출됨 | `CALLED` | 운영자가 호출, 유예 시간 진행 중 | 운영자 |
| 입장 완료 | `ENTERED` | 부스 입장 확정 (종료 상태) | 운영자 |
| 취소 | `CANCELED` | 이용자 자발적 취소 (종료 상태) | 이용자 |
| 노쇼 | `NO_SHOW` | 호출 후 미응답 확정 (종료 상태) | 운영자 |

- `WAITING` / `CALLED` = **활성 상태**. 중복 등록 차단(F-WAI-06) 판정 기준.
- `CALLED` 진입 시각 + 5분 경과 시 운영자 화면에 노쇼 후보로 강조하되, **자동 전이는 하지 않는다**.

### 4.2 혼잡도 등급

| 등급 코드 | 표기(KO) | 표기(EN) | 색상 역할 |
|---|---|---|---|

> 색상값은 3주차 디자인 토큰 정의 시 확정한다. 등급명은 반드시 색상과 함께 텍스트로 표기한다(NFR-U-003).

## 5. 주요 사용자 플로우

### 5.1 QR 웨이팅 (핵심 플로우)

```
1. 이용자가 부스 앞 QR을 기본 카메라로 스캔
2. 브라우저 → U-07 웨이팅 등록 화면 진입 (부스 식별자 포함 URL)
3. 화면에 현재 대기 팀 수 / 예상 대기시간 표시
4. 인원 수 선택 → (선택) 전화번호 입력 시 동의 체크 → [등록]
5. 순번 발급 → U-08 대기표 화면 자동 이동
6. WebSocket 구독 시작, 앞선 팀 호출될 때마다 순번 갱신
7. 내 차례 → 화면 호출 상태 전환 + 브라우저 로컬 알림
   └ 전화번호를 입력했다면 호출 문자 발송 (일일 한도 내)
8. 부스 도착 → 운영자가 [입장 완료] 처리 → 대기표 종료
```

**예외 처리**
| 상황 | 처리 |
|---|---|
| 접수 마감된 부스 QR 스캔 | 등록 버튼 비활성 + 마감 안내, 부스 상세로 유도 |
| 이미 해당 부스에 활성 대기표 보유 | 등록 화면 대신 기존 대기표(U-08)로 이동 |
| WebSocket 단절 | 폴링으로 순번 갱신 지속, 화면에 "연결 재시도 중" 표시 |
| 브라우저 데이터 삭제로 토큰 소실 | 대기표 자동 복원 불가. 이용자가 기억·캡처한 **대기 번호**로 운영자가 조회 (F-WAI-20) |
| 문자 일일 한도 초과 | 문자만 중단, 화면 표시는 정상 동작. `SKIPPED_LIMIT` 기록 (F-WAI-22) |
| 문자 발송 실패 (사업자 장애·번호 오류) | 실패 기록 후 화면 표시 유지. 운영자가 재발송 (F-WAI-23) |
| 호출 후 5분 초과 | 대기표에 "호출 시간 초과, 부스에 문의" 표시. 운영자 판단으로 노쇼 확정 |

### 5.2 혼잡도 관제

```
1. 총괄 운영자가 A-04에서 구역 선택
2. 혼잡도 등급 선택 + 추정 인원 입력 → [저장]
3. 서버: CongestionLog 적재 → WebSocket /topic/congestion 브로드캐스트
4. 접속 중인 모든 이용자 U-01 / U-11 화면 3초 이내 갱신
5. 15분간 갱신 없으면 클라이언트가 UNKNOWN 상태로 전환 표시
```

### 5.3 긴급 공지 전파

```
1. 총괄 운영자가 A-09에서 공지 작성 → [긴급 발행]
2. 서버: Notice 저장 → (I18N-09) 영문 번역 우선 처리 → /topic/notice 브로드캐스트
3. 전 화면 상단 배너 즉시 노출, 탭 시 U-12 상세
```
