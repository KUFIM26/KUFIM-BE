# KUFIM 세션 시작 가이드

이 문서는 **새 세션을 시작하는 사람이나 AI 에이전트**가 프로젝트 맥락을 빠르게 파악하기 위한 안내다.
작업을 시작하기 전에 이 파일을 먼저 읽고, 아래 순서대로 문서를 확인한다.

---

## 1. 30초 요약

**KUFIM** — 건국대학교 축제 통합 정보 플랫폼. 2026학년도 2학기 드림학기제 프로젝트.

| 항목 | 내용 |
|---|---|
| 팀 | 김도현(PM·프론트, 12학점/주 40시간) · 정근녕(백엔드, 3학점/**주 10시간**) |
| 지도교수 | 이상원 (수의과대학) |
| 기간 | 16주. **11주차 축제 현장 적용이 고정 마감** |
| 현재 단계 | 설계 문서 작성 완료. 구현 미착수 |
| 핵심 기능 | QR 스마트 웨이팅 · 메인무대 혼잡도 관제 · 축제 지도 · 관리자 대시보드 |
| 기술 스택 | React + TypeScript / Spring Boot + Java 21 / MySQL + Redis / AWS |

**이 서비스의 존재 이유:** 2025년 일감호축전에서 메인무대 대기줄이 수백 미터인데 예상 대기 시간 안내가 없었다.
운영진은 인원을 직접 세어 구두로 전달했다. 이걸 디지털로 바꾸는 것이 프로젝트의 출발점이다.

## 3. 반드시 알아야 할 결정 사항

이걸 모르고 작업하면 되돌리는 일이 생긴다.

| 결정 | 내용 | 왜 |
|---|---|---|
| **범위 축소** | 계획서의 E(신고)·F(스탬프투어)·G(굿즈)·H(티켓팅)·I(분실물)·멀티이벤트는 **보류** | 주 10시간 백엔드로 16주 안에 소화 불가 |
| **전화번호 선택 입력** | 필수가 아니다. 입력자에게만 호출 문자 발송 | 개인정보 최소 수집 + 이탈 방지 |
| **문자 비용 자비 부담** | 일일 한도·건당 1회 제한 필수. 한도 초과해도 웨이팅은 계속 동작 | 예산 폭주 방지 |
| **관리자 인증은 Redis 세션** | JWT 아님. 강제 로그아웃이 즉시 반영되어야 한다 | 축제 당일 태블릿 분실·교대 대응 |
| **노쇼 자동 전이 없음** | 5분 후 후보 표시만, 확정은 사람이 | 화장실 다녀온 학우가 잘리면 안 된다 |
| **QR은 기본 카메라로 스캔** | 앱 내 스캐너를 만들지 않는다 | 카메라 권한 요구 제거 → 이탈률 감소 |
| **지도는 캠퍼스 도면 기반** | 실지도 오버레이가 아니다. GPS만 카카오맵에서 취득 | 축제 당일 임시 배치는 실지도에 없다 |
| **레포 2개** | `kufim-web`(학생+관리자 라우트 분리) + `kufim-api` | 2인 팀에서 3개는 관리 비용 과다 |

## 4. 작업 원칙

### 4.1 문서를 고쳤으면 반드시 검증한다

```bash
pip install sqlglot
python docs/verify/run_all.py
```

개수 불일치·ID 누락·링크 깨짐은 사람 눈으로 잡을 수 없다. 실제로 초기 검증에서 결함 11건이 나왔다.

| 무엇을 고쳤나 | 무엇을 돌리나 |
|---|---|
| 아무 문서나 | `v5_docs_consistency.py` (**항상**) |
| `sql/schema.sql` · `seed_dev.sql` | `v1`, `v2`, `v3` |
| `design/tokens.css` | `v6` |
| `openapi/kufim-openapi.yaml` | 아래 4.2 |

### 4.2 API를 바꿨으면 3개를 함께 갱신한다

**OpenAPI YAML이 원본이다.** 마크다운 상세 참조와 타입은 생성물이다.

```bash
# 1. openapi/kufim-openapi.yaml 수정
# 2. 마크다운 상세 참조 재생성
python docs/openapi/gen_markdown.py
# 3. TypeScript 타입 재생성
npx openapi-typescript docs/openapi/kufim-openapi.yaml -o docs/openapi/kufim-api.d.ts
# 4. 스펙 검증
python -c "import yaml;from openapi_spec_validator import validate;validate(yaml.safe_load(open('docs/openapi/kufim-openapi.yaml',encoding='utf-8')))"
```

`KUFIM_API_상세참조.md`를 **직접 수정하지 않는다.** 다음 생성에서 덮어써진다.

### 4.3 제안값은 상수로 분리한다

요구사항 명세서에 **(제안)** 으로 표시된 값이 77건 있다(§12에 정리). 개발팀이 임의로 정한 값이라 근거가 약하다.
**하드코딩하지 말고 설정 파일로 빼서** 인터뷰·실측 후 코드 수정 없이 바꿀 수 있게 한다.

### 4.4 놓치기 쉬운 것

- **중복 등록 방지는 DB 제약으로 못 만든다.** MySQL이 부분 유니크 인덱스를 지원하지 않는다. Redis `SETNX` + 트랜잭션 내 재확인이 유일한 방법이며, **동시성 테스트로 반드시 검증**한다
- **혼잡도 만료(15분) 판정은 클라이언트가 한다.** 서버가 브로드캐스트하지 않는다
- **브로드캐스트는 변경분만.** 전체 스냅샷 재전송은 1,000명 환경에서 대역폭 병목
- **문자 발송 실패가 호출 처리를 실패시키면 안 된다**
- **혼잡도 뱃지에서 텍스트나 게이지를 빼지 않는다.** 색만으로는 색각 이상에서 구분 불가

## 6. 검증되지 않은 것

문서에 적혀 있다고 검증된 것은 아니다. 다음은 **아직 확인하지 못했다.**

- 실제 MySQL 8.0에서의 DDL 실행 (SQLite 번역본으로만 검증)
- Redis 대기열 동시성 (서버 코드 없음)
- 실제 응답 시간·동시접속 (9주차 k6)
- 좌표 변환의 현실 정확도 (시드 좌표가 예시값)
- 문자 발송 사업자 가입 가능 여부

자세한 내용은 [검증 보고서](./KUFIM_검증보고서.md) §8을 보라.
