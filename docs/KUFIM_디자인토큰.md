## 1. 설계 전제

### 1.1 왜 라이트 테마 단일인가
축제는 **주간 옥외**와 **야간 옥외**에서 모두 사용된다. 직사광 아래에서는 다크 테마가 오히려 판독이 어렵다.
따라서 **고대비 라이트 테마 단일**로 가고, 야간에는 기기 자동 밝기에 맡긴다.
다크모드는 2단계 접근성 강화 항목으로 보류되어 있다(요구사항 §10).

### 1.2 색상은 정보를 단독으로 전달하지 않는다
NFR-U-003에 따라 혼잡도는 항상 **색상 + 한글 텍스트 + 칸 게이지** 세 채널로 표시한다.
색각 이상 사용자에게 실제로 순서를 전달하는 것은 게이지와 텍스트이며, 색상은 빠른 인지를 돕는 보조 채널이다.
이 결정의 근거는 §6.3의 색각 시뮬레이션 결과에 있다.

## 2. 색상 토큰

### 2.1 기본

| 토큰 | 값 | 용도 |
|---|---|---|
| `--color-bg` | `#FFFFFF` | 페이지 배경 |
| `--color-surface` | `#F2F5F7` | 카드·패널 |
| `--color-text` | `#14181C` | 본문 |
| `--color-text-sub` | `#4C565F` | 보조 텍스트·캡션 |
| `--color-brand` | `#046A38` | 브랜드(건국대 녹색 계열), 주요 버튼 |
| `--color-brand-on` | `#FFFFFF` | 브랜드 위 텍스트 |
| `--color-link` | `#0B5FBF` | 링크 |
| `--color-danger` | `#B3261E` | 오류·경고 텍스트 |
| `--color-border` | `#767E86` | 상호작용 요소 테두리 (3:1 충족) |
| `--color-divider` | `#DCE1E6` | 장식용 구분선 (대비 요구 없음) |
| `--color-focus` | `#0B5FBF` | 포커스 링 |

> **테두리를 두 종류로 나눈 이유**: WCAG는 의미를 갖는 UI 경계에 3:1을 요구한다. 흔히 쓰는 연회색(`#DCE1E6`)은 1.32:1로 이 기준에 한참 못 미친다. 입력 필드·버튼처럼 **경계 자체가 정보인 곳**은 `--color-border`를, 단순 장식 구분선은 `--color-divider`를 쓴다.

### 2.2 혼잡도 (STG-004)

| 단계 | 배경 | 텍스트 | 테두리 | 게이지 | 한글 표기 |
|---|---|---|---|---|---|
| `SMOOTH` | `#137C43` | `#FFFFFF` | `#0E5F33` | ■□□□ | 원활 |
| `NORMAL` | `#F5C518` | `#2A2100` | `#8A6D00` | ■■□□ | 보통 |
| `CROWDED` | `#BF5809` | `#FFFFFF` | `#93380A` | ■■■□ | 혼잡 |
| `VERY_CROWDED` | `#C1121F` | `#FFFFFF` | `#8A0D16` | ■■■■ | 매우 혼잡 |
| `UNKNOWN` | `#F2F5F7` | `#4C565F` | `#767E86` | □□□□ | 정보 확인 중 |

- `NORMAL`만 어두운 텍스트를 쓴다. 노란 배경에 흰 글씨는 4.5:1을 만족할 수 없다.
- 노란 배경은 흰 페이지와 1.63:1로 구분되지 않으므로 **테두리가 필수**다. 다른 단계도 일관성을 위해 동일하게 테두리를 둔다.
- `UNKNOWN`은 서버가 반환하지 않는다. 클라이언트가 `serverTime - updatedAt > 15분`일 때 표시한다(F-STG-07).

## 6. 접근성 검증 결과

아래 수치는 실제로 계산해 확인한 값이다.

### 6.1 UI 토큰 명도 대비

### 6.2 혼잡도 뱃지

| 단계 | 텍스트 대비 | 테두리 / 페이지 대비 |
|---|---|---|
| SMOOTH | 5.26:1 | 7.77:1 |

전 항목이 텍스트 4.5:1, 경계 3.0:1을 만족한다.

### 6.3 색각 이상 시뮬레이션

혼잡도 배경색 4종을 색각 이상 조건에서 변환한 뒤 최소 색거리를 측정했다.

| 조건 | 최소 색거리 | 가장 혼동되는 쌍 |
|---|---|---|
| 1형 색각(protanopia) | 52.1 | CROWDED ↔ VERY_CROWDED |
| 2형 색각(deuteranopia) | 27.5 | CROWDED ↔ VERY_CROWDED |
| 3형 색각(tritanopia) | 12.7 | CROWDED ↔ VERY_CROWDED |

> **해석**: `혼잡`과 `매우 혼잡`은 2·3형 색각에서 색만으로는 구분이 어렵다.
> 이는 관례적인 주황–빨강 배색을 쓰는 한 피할 수 없다. 색을 바꿔 억지로 떨어뜨리면 "혼잡"이 갈색처럼 보여 일반 사용자의 직관을 해친다.
> 따라서 **칸 게이지(■■■□ vs ■■■■)와 한글 텍스트가 실제 구분 채널**이며, 색상은 보조로만 쓴다. 이 원칙은 NFR-U-003으로 이미 명문화되어 있다.
> 구현 시 혼잡도 뱃지에서 텍스트나 게이지를 생략하는 축약형을 만들지 않는다.

### 6.4 검증 방법
- 명도 대비: WCAG 2.1 상대 휘도 공식
- 색각 시뮬레이션: LMS 색공간 변환 후 sRGB 역변환, 유클리드 색거리 측정
- 검증 스크립트는 개발 레포 `scripts/verify-tokens` 로 이관해 CI에서 회귀 검사한다

## 7. 사용 규칙

1. **하드코딩한 색상 값을 컴포넌트에 직접 쓰지 않는다.** 반드시 토큰을 경유한다.
2. **본문에 `--text-xs`(14px)를 쓰지 않는다.** COM-004의 16px 최소치를 어기게 된다.
3. **터치 가능한 요소는 시각 크기와 무관하게 히트 영역 44px 이상을 확보한다.**
4. **혼잡도 표시는 색·텍스트·게이지 세 가지를 항상 함께 렌더한다.**
5. 토큰을 추가·변경하면 §6 검증을 다시 돌리고 결과 표를 갱신한다.
