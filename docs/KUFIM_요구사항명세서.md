## 1. 문서 개요

### 1.1 목적
본 문서는 대학 축제 통합 웹 플랫폼 **KUFIM**이 만족해야 할 기능·비기능 요구사항을 정의한다.
1주차 산출물이며, 이후 기능 정의서·ERD·API 설계·화면 설계의 기준 문서로 사용한다.

### 1.2 문서 범위
- 학생용 모바일 웹(이하 **User Web**)
- 운영진용 관리자 웹(이하 **Admin Web**)
- 이를 지원하는 백엔드 API 및 실시간 서버

### 1.3 참고 문서
- `2026-2_드림학기제_김도현_기타(자율형).pdf` — 프로젝트 계획서
- `내용.txt` — 드림학기제 신청 내역(주차별 계획)

### 1.4 용어 정의

| 용어 | 정의 |
|---|---|
| 이용자 | 회원가입 없이 User Web을 사용하는 축제 방문객 (학생·교직원·지역민·유학생) |
| 부스 운영자 | 개별 부스/푸드트럭에서 웨이팅 호출을 수행하는 관리자 |
| 총괄 운영자 | 총학생회 소속으로 전체 콘텐츠·공지·혼잡도를 관리하는 관리자 |
| 웨이팅 | 부스 이용을 위한 디지털 줄서기 등록 건 (1건 = 1팀) |
| 대기표 | 이용자에게 발급되는 웨이팅 조회 화면 |
| 혼잡도 | 메인무대 구역별 인파 밀집 정도(4단계 + 추정 인원) |
| 익명 토큰 | 최초 접속 시 브라우저에 저장되는 UUID. 웨이팅 소유권 판별용 |
| 도면 좌표 | 캠퍼스 도면 이미지 내부의 픽셀 기반 (x, y) 좌표계 |

### 1.5 요구사항 표기 규칙
- ID 형식: `<도메인>-<번호>`
- 우선순위: **M**(Must, 필수) / **S**(Should, 권장) / **C**(Could, 선택)
- 본 문서의 모든 **M** 요구사항은 11주차 현장 적용 시점까지 완료를 전제로 한다.
- **`(제안)`** 표시: 개발팀이 임의로 정한 값이다. 근거가 약하므로 총학생회 인터뷰·지도교수 미팅에서 확정한다.
  전체 목록은 §12에 모아 두었다. **구현은 이 값으로 시작하되, 상수로 분리해 나중에 바꿀 수 있게 한다.**

### 1.6 요구사항 작성 원칙
1. **숫자를 쓴다.** "빠르게"가 아니라 "3초 이내", "여러 번"이 아니라 "최대 5회".
2. **예외를 쓴다.** 정상 흐름만 적힌 요구사항은 구현 단계에서 반드시 되묻게 된다.
3. **서버가 강제하는 것과 화면만 막는 것을 구분한다.** 프론트 검증은 통제가 아니다(NFR-S-002).
4. **모르는 것은 `(제안)`으로 표시하고 넘어간다.** 비워 두면 구현자가 임의로 정하게 된다.

## 4. 기능 요구사항

### 4.1 COM — 공통

| ID | 요구사항 | 설명 | 우선순위 |
|---|---|---|---|
| COM-001 | 비회원 이용 | 회원가입·로그인 없이 모든 조회 기능과 웨이팅을 이용할 수 있다.<br>- **로그인 화면 자체를 이용자에게 노출하지 않는다.** 관리자 로그인은 별도 경로(`/admin`)로만 접근한다.<br>- 어떤 기능도 "로그인이 필요합니다"로 막히지 않는다. | M |
| COM-002 | 익명 토큰 발급 | 최초 접속 시 UUID v4를 생성해 브라우저에 저장하고, 이후 모든 요청의 `X-Client-Token` 헤더에 첨부한다.<br>- **저장소:** `localStorage` 키 `kufim_client_token` **(제안)**<br>- **만료 없음.** 축제 기간 내내 동일 값을 유지한다.<br>- 토큰이 없거나 형식이 잘못되면 클라이언트가 즉시 재발급하고, 서버는 웨이팅 요청에 한해 `400 C003`으로 거부한다.<br>- **개인정보가 아니다.** 브라우저가 생성하며 개인을 식별하지 않는다.<br>- 시크릿 모드·브라우저 변경 시 새 토큰이 발급되어 기존 대기표를 찾을 수 없다(→ WAI-018). | M |
| COM-003 | 모바일 반응형 | User Web은 폭 **360~430px**를 기준으로 설계한다.<br>- **최소 320px**까지 레이아웃이 깨지지 않아야 한다 **(제안)**<br>- 어떤 폭에서도 **가로 스크롤이 발생하지 않는다.** 넓은 표·도면은 자체 스크롤 영역에 넣는다.<br>- 가로 회전 시 자동 확대되지 않도록 `text-size-adjust: 100%`를 적용한다.<br>- Admin Web은 PC·태블릿 가로(1024px 이상) 기준으로 별도 설계한다(ADM-011). | M |
| COM-004 | 야외·야간 시인성 | 직사광과 야간 환경을 모두 고려한 시각 기준을 적용한다.<br>- 본문 텍스트 **명도 대비 4.5:1 이상**, 의미를 갖는 UI 경계는 **3:1 이상**<br>- 기본 폰트 **16px 이상**. 캡션용 14px는 본문에 쓰지 않는다.<br>- 터치 타깃은 시각 크기와 무관하게 **히트 영역 44×44px 이상**<br>- **색상 단독으로 정보를 전달하지 않는다.** 항상 텍스트 또는 도형을 함께 쓴다(→ NFR-U-003).<br>- 대비 수치는 계산으로 검증하며, 토큰 변경 시 재검증한다. | M |
| COM-005 | 실시간 채널 | 혼잡도·웨이팅 순번·공지는 **단일 WebSocket 연결(STOMP over SockJS)** 로 수신한다.<br>- 화면당 연결을 새로 만들지 않고 앱 전체에서 하나를 공유한다.<br>- 구독 토픽은 화면 진입 시 추가하고 이탈 시 해제한다.<br>- 동시 구독 토픽은 이용자당 **최대 5개** **(제안)** — 대기표를 여러 개 가진 경우를 고려한 값이다. | M |
| COM-006 | 연결 복구 | WebSocket 단절 시 자동으로 재연결한다.<br>- **지수 백오프:** 1초 → 2 → 4 → 8 → 16초, **최대 5회** **(제안)**<br>- 5회 실패 시 **폴링으로 전환**하고 이후 30초마다 재연결을 재시도한다.<br>- **폴링 주기:** 대기표 화면 5초, 그 외 화면 15초 **(제안)**<br>- 재연결 성공 시 폴링을 중단하고 구독을 자동 복구한다.<br>- 연결 상태를 화면에 표시한다(정상 / 재연결 중 / 오프라인). | M |
| COM-007 | 오프라인 대응 | 네트워크 오류 시에도 화면이 비지 않아야 한다.<br>- 마지막으로 성공한 응답을 유지하고 **"정보 갱신 중"** 배지를 표시한다.<br>- 마지막 갱신 후 **30초** 경과 시 배지를 경고색으로 전환한다 **(제안)**<br>- **빈 화면·스피너만 남는 상태를 만들지 않는다.** 축제 현장에서 가장 흔한 실패 모드다.<br>- 쓰기 요청(등록·취소) 실패는 명확히 알리고 **자동 재시도하지 않는다.** 중복 등록을 유발한다. | M |
| COM-008 | 긴급 공지 배너 | 총괄 운영자가 발행한 긴급 공지를 전 화면 상단에 즉시 노출한다.<br>- 스크롤과 무관하게 **상단 고정**한다.<br>- 이용자가 닫을 수 있으나, **새로 발행된 공지는 다시 노출**한다(공지 ID 기준 판단).<br>- 동시에 여러 건이면 **가장 최근 1건만** 표시하고 나머지는 공지 목록에서 확인한다 **(제안)**<br>- 배너 탭 시 공지 상세로 이동한다. | M |
| COM-009 | 전역 내비게이션 | 하단 고정 탭으로 주요 화면을 오간다.<br>- 탭 구성: **프로그램 / 지도 / 내 대기표 / 무대 현황** (4개)<br>- 활성 탭을 색상과 아이콘 채움으로 함께 표시한다(COM-004).<br>- **활성 대기표가 있으면 "내 대기표" 탭에 개수 뱃지**를 표시한다.<br>- 하단 탭이 콘텐츠를 가리지 않도록 본문 하단에 여백을 확보한다(iOS safe area 포함). | M |
| COM-010 | 개인정보 고지·조건부 동의 | 전화번호는 선택 입력이며, **입력하는 경우에만** 동의 절차를 노출한다.<br>- 고지 항목: 수집 항목(휴대전화번호), 목적(호출 안내 문자), 보유 기간(축제 종료 후 7일 이내 파기)<br>- **미입력자에게는 동의 UI를 표시하지 않는다.** 수집하지 않는데 동의를 받으면 오해를 만들고 조작이 1회 늘어난다.<br>- 전화번호가 있는데 동의가 없으면 **서버가 `400 C002`로 거부**한다. 프론트 검증만으로 처리하지 않는다.<br>- 브라우저 데이터 삭제 시 대기표를 복원할 수 없다는 안내를 등록·대기표 화면에 모두 표시한다. | M |

### 4.2 PRG — 프로그램 안내

| ID | 요구사항 | 설명 | 우선순위 |
|---|---|---|---|
| PRG-001 | 라인업 조회 | 초청 가수와 학생 공연 출연진을 조회한다.<br>- **구분 표시:** 초청 / 학생 / 행사를 시각적으로 구분한다.<br>- 각 항목에 공연명·출연진·무대·시각·이미지를 표시한다.<br>- 이미지가 없으면 기본 이미지를 쓰되 고정 비율을 유지해 레이아웃이 흔들리지 않게 한다.<br>- 관리자가 지정한 표시 순서를 따르며, 미지정 시 시작 시각 오름차순으로 정렬한다. | M |
| PRG-002 | 타임테이블 | 일자별·무대별 공연 시간표를 제공한다.<br>- **일자 탭**으로 날짜를 전환하며, 기본값은 오늘(축제 기간 밖이면 첫날)이다.<br>- 무대별로 그룹화하고 각 그룹 안에서 시작 시각 오름차순으로 정렬한다.<br>- **현재 시각 기준선**을 표시해 지금이 어디인지 즉시 알 수 있게 한다.<br>- 종료된 공연은 흐리게 처리하되 목록에서 제거하지 않는다.<br>- 시간이 겹치는 공연은 나란히 표시한다(무대가 다르면 정상 상황이다). | M |
| PRG-003 | 현재·다음 공연 | 홈 화면 상단에 진행 중인 공연과 다음 공연을 강조한다.<br>- **서버 시각 기준**으로 판정한다. 기기 시각이 틀어져도 결과가 달라지지 않아야 한다.<br>- 진행 중인 공연에는 **남은 시간**을, 다음 공연에는 **시작까지 남은 시간**을 표시한다.<br>- 진행 중인 공연이 여러 개(무대가 다름)면 **메인무대를 우선** 표시한다 **(제안)**<br>- 둘 다 없으면 "예정된 공연이 없습니다"를 표시하고 영역을 접는다. | M |
| PRG-004 | 부스 목록 | 부스·푸드트럭 목록을 조회한다.<br>- **카테고리 다중 선택 필터:** 체험·음식·푸드트럭·홍보·공연전시<br>- **정렬:** 대기 적은 순(기본) / 이름순 **(제안)**<br>- 각 항목에 부스명·카테고리·운영시간·썸네일·**현재 대기 팀 수**를 표시한다.<br>- **페이지네이션을 두지 않고 전량 반환**한다. 부스는 50~100개 규모이며 현장 네트워크에서 추가 왕복이 더 비싸다.<br>- 웨이팅 미사용 부스는 대기 정보 대신 운영시간만 표시한다. | M |
| PRG-005 | 부스 상세 | 부스의 전체 정보를 확인하고 웨이팅으로 진입한다.<br>- 표시 항목: 소개, 운영시간, 이미지 여러 장, 부스 개별 안내 문구, 지도 위치, 현재 대기 현황<br>- **웨이팅 사용 부스면 등록 버튼을, 접수 마감이면 비활성 버튼과 사유**를 표시한다.<br>- 이미 활성 대기표가 있으면 등록 대신 **"내 대기표 보기"** 로 전환한다.<br>- 지도 위치 탭 시 해당 핀이 선택된 상태로 지도 화면을 연다. | M |
| PRG-006 | 콘텐츠 즉시 반영 | 관리자의 등록·수정 결과가 이용자 화면에 빠르게 반영된다.<br>- 조회 API 응답 캐시 TTL **30초** **(제안)**<br>- 이용자가 화면을 당겨 새로고침하면 캐시를 무시하고 즉시 재조회한다.<br>- **타임테이블 변경은 캐시를 기다리지 않는다.** 당일 일정 변경은 안전과 직결되므로 관리자 저장 시 캐시를 즉시 무효화한다. | M |
| PRG-007 | 키워드 검색 | 부스명·공연명을 검색한다.<br>- **부분 일치**를 지원한다(예: "주점" → "컴퓨터공학부 주점")<br>- **2자 이상** 입력 시 검색을 시작하며 **300ms 디바운스**를 적용한다 **(제안)**<br>- 대소문자·공백을 무시하고 비교한다.<br>- 결과가 없으면 "검색 결과가 없습니다"와 함께 필터 초기화 버튼을 제공한다. | S |
| PRG-008 | 일정 변경 표식 | 시작 시각이 변경된 공연을 눈에 띄게 표시한다.<br>- 관리자가 시작 시각을 수정하면 서버가 변경 표식을 설정한다.<br>- 목록·상세에 **"시간 변경됨"** 배지를 표시한다.<br>- 배지는 축제 종료까지 유지한다. 언제 바뀌었는지보다 **바뀌었다는 사실**이 중요하다. | S |

### 4.3 STG — 메인무대 관제

| ID | 요구사항 | 설명 | 우선순위 |
|---|---|---|---|
| STG-001 | 구역 정의 | 총괄 운영자는 무대를 여러 구역으로 나누어 관리한다.<br>- 무대당 구역 **최대 10개** **(제안)** — 그 이상은 운영자가 입력을 감당하지 못한다.<br>- 구역명은 현장 용어를 그대로 쓴다(예: "스탠딩 A구역", "입장 대기열").<br>- 표시 순서를 지정할 수 있으며 이용자 화면도 같은 순서를 따른다.<br>- 혼잡도 이력이 있는 구역은 삭제할 수 없다. 비활성 처리만 가능하다. | M |
| STG-002 | 혼잡도 입력 | 운영자가 구역별 혼잡도를 4단계로 입력한다.<br>- 단계: `원활` / `보통` / `혼잡` / `매우 혼잡`<br>- **입력은 3초 안에 끝나야 한다.** 단계 버튼을 크게 배치하고 확인 절차를 두지 않는다.<br>- **권장 입력 주기 5분** **(제안)** — 인터뷰(Q14)로 현장 감당 가능 여부를 확인한다.<br>- 직전과 동일한 값도 허용한다. "여전히 혼잡함"을 갱신하는 것도 정보다.<br>- 입력할 때마다 이력에 append 하며 기존 값을 수정·삭제하지 않는다. | M |
| STG-003 | 추정 인원 입력 | 혼잡도와 함께 추정 인원 수를 입력한다.<br>- 범위 **0 ~ 9999명**, 정수만 **(제안)**<br>- **선택 입력이다.** 인원을 셀 수 없는 상황에서 등급만 올리는 것을 막지 않는다.<br>- 입력 편의를 위해 **±50 단위 증감 버튼**을 함께 제공한다 **(제안)**<br>- 등급과 인원이 모순되어도(예: 원활 + 800명) 막지 않는다. 현장 판단이 우선이다. | M |
| STG-004 | 색상·숫자 표시 | 이용자 화면에 혼잡도를 다중 채널로 표시한다.<br>- **색상 + 한글 등급명 + 칸 게이지** 세 가지를 항상 함께 렌더한다.<br>- 추정 인원이 있으면 숫자를 함께 표시하고, 없으면 등급만 표시한다.<br>- **텍스트나 게이지를 생략한 축약형을 만들지 않는다.** 색만으로는 2·3형 색각에서 `혼잡`과 `매우 혼잡`이 구분되지 않는다.<br>- 마지막 갱신 시각을 상대 시간으로 표시한다(예: "3분 전"). | M |
| STG-005 | 실시간 반영 | 혼잡도 변경을 접속 중인 전체 이용자에게 전파한다.<br>- 관리자 저장부터 이용자 화면 갱신까지 **3초 이내**<br>- **변경된 구역 하나만** 브로드캐스트한다. 전체 스냅샷 재전송은 1,000명 환경에서 대역폭 병목이다.<br>- WebSocket이 끊긴 이용자는 폴링으로 최대 15초 이내에 따라잡는다(COM-006). | M |
| STG-006 | 입장 통제 상태 | 무대별 입장 가능 여부를 표시한다.<br>- 상태: `입장 가능` / `입장 통제 중`<br>- 통제 전환은 **총괄 운영자만** 수행하며 즉시 브로드캐스트된다.<br>- 통제 중에는 이용자 화면 상단에 경고색 배너를 표시한다.<br>- 상태 변경은 감사 로그에 기록한다. 안전 관련 판단의 근거가 된다. | M |
| STG-007 | 갱신 지연 표시 | 오래된 혼잡도를 최신 정보처럼 보여주지 않는다.<br>- 마지막 갱신 후 **15분** 경과 시 `정보 확인 중`으로 전환한다 **(제안)**<br>- **판정은 클라이언트가 한다.** 서버가 15분마다 상태를 바꿔 브로드캐스트하면 불필요한 트래픽이 생기고, 접속 시점이 제각각이라 어차피 클라이언트 계산이 필요하다.<br>- 서버는 항상 원본 값과 서버 시각을 함께 반환한다. 기기 시각을 신뢰하지 않는다.<br>- 관리자 화면에는 **갱신이 밀린 구역을 강조**해 입력을 유도한다. | M |
| STG-008 | 혼잡도 이력 | 모든 입력을 시각·입력자와 함께 보존한다.<br>- **append-only.** UPDATE·DELETE 하지 않는다.<br>- 사후 분석 보고서(계획서 최종 산출물)의 원자료가 된다.<br>- CSV로 내보낼 수 있어야 한다(ADM-010). | M |
| STG-009 | 추이 그래프 | 이용자에게 최근 혼잡도 변화를 보여준다.<br>- 기본 조회 구간 **최근 3시간** **(제안)**<br>- 구역별 라인 또는 계단 차트로 표시한다.<br>- 우선순위가 낮으므로 1단계 일정이 밀리면 가장 먼저 뒤로 미룬다. | C |

### 4.4 WAI — 스마트 웨이팅

> 이 서비스의 핵심 기능이다. 요구사항 수가 가장 많고 6주차에 집중된다.

| ID | 요구사항 | 설명 | 우선순위 |
|---|---|---|---|
| WAI-001 | QR 생성 | 총괄 운영자가 부스별 고유 QR을 발급한다.<br>- QR에는 `https://{도메인}/w/{boothCode}` 형태의 URL을 인코딩한다.<br>- `boothCode`는 **12자리 난수**이며 혼동되는 문자(0/O, 1/I/l)를 제외한 집합을 쓴다 **(제안)**<br>- **추측 불가능해야 한다.** 부스 ID를 그대로 노출하면 타 부스 QR을 유추할 수 있다(NFR-S-004).<br>- 재발급 시 기존 코드는 즉시 무효화되고 이전 QR은 `404 B002`로 응답한다.<br>- **인쇄·부착 이후 재발급은 현장 혼선을 유발**하므로 확인 절차를 둔다. | M |
| WAI-002 | QR 진입 | QR 스캔 시 해당 부스의 웨이팅 등록 화면으로 즉시 진입한다.<br>- **앱 내 스캐너를 만들지 않는다.** 스마트폰 기본 카메라가 URL을 열게 한다. 카메라 권한 요구를 없애 이탈률을 낮춘다.<br>- 진입 시 부스 정보와 대기 현황을 함께 로드해 **한 화면에서 판단**할 수 있게 한다.<br>- 이미 활성 대기표가 있으면 등록 화면 대신 대기표로 이동한다.<br>- 접수 마감 상태면 등록 버튼을 비활성화하고 사유를 표시한다. | M |
| WAI-003 | 웨이팅 등록 | 인원 수를 입력해 줄을 선다.<br>- **인원 수 1~10명**, 기본값 2명 **(제안)**. 버튼 방식으로 선택해 키보드를 띄우지 않는다.<br>- **전화번호는 선택 입력**이다. 입력하면 호출 문자를 받고, 안 하면 화면 표시로만 진행한다.<br>- 전화번호 입력 시 동의 체크가 필수이며 없으면 서버가 `400 C002`로 거부한다.<br>- **등록 완료까지 3회 이하 조작**으로 끝나야 한다(NFR-U-001).<br>- 등록 즉시 대기표 화면으로 전환하며 별도 확인 단계를 두지 않는다. | M |
| WAI-004 | 중복 등록 방지 | 같은 사람이 한 부스에 여러 번 줄 서는 것을 막는다.<br>- 판정 기준: 동일 `부스 + 익명 토큰`에 **활성 상태(대기 중·호출됨) 1건**<br>- **DB 제약으로 표현할 수 없다.** 부분 유니크 인덱스가 필요한데 MySQL이 지원하지 않는다.<br>- Redis `SETNX`로 1차 차단하고 등록 트랜잭션 안에서 재확인한다.<br>- **반드시 동시성 테스트로 검증한다.** 여기가 깨지면 현장에서 줄이 꼬이고 되돌릴 방법이 없다.<br>- 취소·입장·노쇼로 종료되면 즉시 재등록할 수 있다. | M |
| WAI-005 | 대기 현황 표시 | 등록 전후 모두 현재 대기 상황을 보여준다.<br>- 표시 항목: **현재 대기 팀 수**, 예상 대기시간, 접수 상태<br>- 등록 전에는 "지금 등록하면 몇 번째인지"를, 등록 후에는 "앞에 몇 팀 남았는지"를 보여준다.<br>- 대기 팀 수는 Redis에서 읽어 DB에 접근하지 않는다(NFR-P-001).<br>- 접수 마감 시 대기 팀 수는 계속 표시하되 등록 경로를 막는다. | M |
| WAI-006 | 예상 대기시간 산출 | 앞선 팀 수와 최근 호출 속도로 예상 시간을 계산한다.<br>- **산출식:** `앞선 팀 수 × 최근 호출 간격 이동 평균`<br>- **표본:** 최근 **10건**의 호출 간격 **(제안)**<br>- **표본이 3건 미만이면 "산출 중"** 으로 표시하고 숫자를 내보내지 않는다 **(제안)**. 초반에 튀는 값을 보여주면 신뢰를 잃는다.<br>- **5분 단위로 반올림**해 표시한다 **(제안)**. "23분"보다 "약 25분"이 현실적이다.<br>- **최대 표시 120분** **(제안)**. 그 이상은 "2시간 이상"으로 표시한다.<br>- 호출 간격이 **30분을 초과한 건은 표본에서 제외**한다 **(제안)**. 운영자 휴식·교대가 평균을 왜곡한다. | M |
| WAI-007 | 내 순번 실시간 갱신 | 앞선 팀이 빠질 때마다 내 순번이 자동으로 줄어든다.<br>- 앞선 팀의 호출·취소·노쇼 시 **3초 이내** 반영<br>- **앞선 팀 전체에 개별 조회를 돌리지 않는다.** 호출된 팀보다 뒤에 있는 인원에게 "1 감소" 이벤트를 일괄 발행한다.<br>- WebSocket 단절 시 5초 폴링으로 대체한다(COM-006).<br>- 순번이 0이 되면 곧 호출됨을 예고하는 문구를 표시한다 **(제안)**. | M |
| WAI-008 | 호출 상태 표시 | 내 차례가 되었음을 확실히 알린다.<br>- 대기표 화면 전체를 **호출 상태로 전환**한다. 색·크기·문구를 모두 바꿔 힐끗 봐도 알 수 있게 한다.<br>- **브라우저 알림 권한이 허용된 경우 로컬 알림**을 함께 발생시킨다.<br>- 알림 권한은 등록 직후가 아니라 **대기표 화면 진입 후 자연스러운 시점**에 요청한다 **(제안)**. 즉시 요청하면 대부분 거부한다.<br>- 진동·소리는 사용하지 않는다 **(제안)**. 공연 중 방해가 된다.<br>- 전화번호를 입력한 경우 문자도 함께 발송된다(WAI-019). | M |
| WAI-009 | 웨이팅 취소 | 대기 중 언제든 줄에서 빠진다.<br>- **확인 다이얼로그를 1회** 거친다. 실수 취소는 되돌릴 수 없다.<br>- 취소 즉시 대기열에서 제거하고 뒤 순번에 전파한다.<br>- **호출된 이후에는 이용자가 취소할 수 없다.** 운영자가 노쇼로 처리한다. 부스 앞에서 상태가 엇갈리는 것을 막기 위함이다.<br>- 취소 후 같은 부스에 즉시 재등록할 수 있다(맨 뒤로 간다). | M |
| WAI-010 | 대기표 재접속 | 브라우저를 닫았다 열어도 대기표를 되찾는다.<br>- 익명 토큰으로 활성 대기표를 자동 복원한다.<br>- 앱 진입 시 활성 대기표가 있으면 홈 화면에 **바로가기 카드**를 표시한다 **(제안)**<br>- **브라우저 데이터 삭제·기기 변경 시에는 복원할 수 없다.** 이 한계를 화면에 명시하고 WAI-018로 완화한다. | M |
| WAI-011 | 운영자 호출 | 부스 운영자가 다음 팀을 부른다.<br>- **가장 오래 기다린 팀**을 호출한다(등록 시각 기준 선입선출).<br>- 두 운영자가 동시에 눌러도 **한 팀만 호출된다.** Redis `ZPOPMIN`으로 원자적으로 처리한다.<br>- 호출할 팀이 없으면 `409 W009`로 응답하고 "대기 중인 팀이 없습니다"를 표시한다.<br>- 특정 팀을 지목해 호출하는 경로도 제공한다(현장에서 순서 조정이 필요한 경우).<br>- **호출 버튼은 화면에서 가장 크게 배치**한다 **(제안)**. 운영자는 장갑을 끼거나 손이 젖은 상태일 수 있다. | M |
| WAI-012 | 상태 전이 | 웨이팅은 정해진 경로로만 상태가 바뀐다.<br>- 허용 전이: `등록 → 대기 중`, `대기 중 → 호출됨`, `대기 중 → 취소`, `호출됨 → 입장 완료`, `호출됨 → 노쇼`<br>- **그 외 전이는 서버가 `409`로 거부**한다(`W007` 호출 불가 상태, `W008` 입장·노쇼 불가 상태).<br>- 모든 전이를 수행자·시각과 함께 이력에 기록한다.<br>- 종료 상태(입장·취소·노쇼)에서는 어떤 전이도 일어나지 않는다. | M |
| WAI-013 | 노쇼 처리 | 호출했는데 오지 않은 팀을 정리한다.<br>- 호출 후 **5분** 경과 시 운영자 화면에 **노쇼 후보로 강조** 표시한다 **(제안)**<br>- **자동으로 전이하지 않는다.** 확정은 반드시 운영자가 한다. 화장실에 다녀온 학우가 자동으로 잘리는 상황을 막기 위함이다.<br>- 이용자 화면에는 남은 유예 시간을 표시한다.<br>- 노쇼 처리 후 이용자는 같은 부스에 재등록할 수 있다. | M |
| WAI-014 | 접수 중단·재개 | 재료 소진·마감 시 신규 등록을 막는다.<br>- 운영자가 토글로 전환하며 즉시 반영된다.<br>- **이미 줄 선 팀은 유지된다.** 중단은 신규 등록만 막는다.<br>- 중단 상태에서 QR을 스캔하면 등록 화면 대신 마감 안내를 표시한다.<br>- 부스 목록·지도에도 마감 상태를 표시해 헛걸음을 줄인다. | M |
| WAI-015 | 대기열 동시성 | 동시 등록에도 순번이 꼬이지 않는다.<br>- 순번 부여는 Redis 원자적 연산(`INCR`, `ZADD`)으로 처리한다.<br>- **동시 100건 등록 시 번호 중복·누락이 0이어야 한다** **(제안)** — 이 값을 테스트 기준으로 삼는다.<br>- Testcontainers로 실제 Redis를 띄워 검증한다. 목(mock)으로는 동시성을 검증할 수 없다.<br>- Redis 유실 시 DB의 활성 웨이팅으로 대기열을 재구성한다(NFR-R-003). | M |
| WAI-016 | 이용 이력 집계 | 사후 분석에 쓸 원자료를 남긴다.<br>- 기록 항목: 등록·호출·입장·취소·노쇼 시각, 인원 수, 수행자<br>- **`등록 → 호출` 구간이 실제 대기 시간**이며, 계획서의 "대기 시간 단축 효과 정량화"의 근거가 된다.<br>- 상태 전이를 별도 이력에 append 한다. 취소 후 재등록 같은 예외 경로는 현재 상태만으로 추적할 수 없다.<br>- CSV 내보내기를 제공한다(ADM-010). | M |
| WAI-017 | 내 대기표 목록 | 여러 부스에 줄 선 경우를 한 화면에서 관리한다.<br>- 활성 대기표를 **순번이 임박한 순**으로 정렬한다 **(제안)**<br>- 동시 등록 가능 부스 수를 **최대 5개로 제한**한다 **(제안)**. 무제한 허용하면 한 사람이 여러 줄을 점유해 실제 대기가 왜곡된다.<br>- 각 카드에 부스명·순번·예상 시간·문자 수신 여부를 표시한다. | S |
| WAI-018 | 대기 번호 현장 조회 | 대기표를 잃은 이용자를 현장에서 찾아준다.<br>- 등록 완료 화면에 **대기 번호를 가장 크게 표시**하고 캡처를 유도한다.<br>- 운영자 화면에서 **대기 번호로 검색**해 해당 대기표를 조회·처리할 수 있다.<br>- 검색은 부스 내에서만 동작한다(번호는 부스별 일련번호다).<br>- **이 요구사항은 완화책이지 해소책이 아니다.** 번호도 기억 못 하는 경우의 처리 방식은 운영 매뉴얼에서 정한다. | M |
| WAI-019 | 호출 문자 발송 | 전화번호를 입력한 이용자에게 호출 문자를 보낸다.<br>- 호출 처리와 **같은 흐름에서** 발송을 요청한다.<br>- 문구에는 **부스명과 대기 번호**를 포함한다 **(제안)** — 여러 부스에 줄 선 경우를 구분하기 위함이다.<br>- **발송 실패가 호출 처리를 실패시키지 않는다.** 실패를 기록하고 화면 표시는 정상 진행한다.<br>- 전화번호 미입력자는 `SKIPPED_NO_PHONE`으로 기록한다. 왜 문자가 안 갔는지 현장에서 확인할 수 있어야 한다. | M |
| WAI-020 | 문자 재발송 | 도달하지 않은 문자를 다시 보낸다.<br>- **운영자만 실행할 수 있다.** 이용자가 반복 요청하면 비용이 통제되지 않는다.<br>- 대기표 1건당 재발송 **최대 2회** **(제안)**<br>- 재발송도 일일 한도에 포함된다.<br>- 전화번호가 없으면 `409 W010`으로 거부한다. | M |
| WAI-021 | 발송 한도 관리 | 자비 부담 비용이 폭주하지 않게 막는다.<br>- **웨이팅 1건당 호출 문자 1회**로 제한한다(재발송은 별도 집계).<br>- **일일 발송 한도**를 설정하고 초과 시 발송을 중단한다. 한도 값은 예산 확정 후 산정한다(TBD-07).<br>- **한도를 초과해도 웨이팅 기능은 계속 동작한다.** 문자만 끊기고 화면 표시로 자동 전환하며 `SKIPPED_LIMIT`으로 기록한다.<br>- 잔여 한도가 **10% 미만**이면 관리자 화면에 경고를 표시한다 **(제안)**. | M |
| WAI-022 | 발송 이력·비용 집계 | 얼마나 썼는지 실시간으로 안다.<br>- 발송 성공·실패·건너뜀을 **사유와 함께** 기록한다.<br>- 건당 단가를 함께 저장해 누적 비용을 산출한다.<br>- 관리자 현황판에 **오늘 발송 수 / 잔여 한도 / 누적 비용**을 표시한다.<br>- **발송 이력에 전화번호를 저장하지 않는다.** 웨이팅의 전화번호 하나만 파기하면 개인정보가 전부 사라지도록 하기 위함이다. | M |

### 4.5 MAP — 축제 지도

| ID | 요구사항 | 설명 | 우선순위 |
|---|---|---|---|
| MAP-001 | 도면 지도 렌더링 | 축제용 캠퍼스 도면 이미지를 기반으로 지도를 그린다.<br>- **실지도 API 위에 오버레이하지 않는다.** 축제 당일 임시 부스 배치는 실지도에 없으며, 도면이 학우에게 훨씬 직관적이다.<br>- 도면 형식 **WebP 우선**, 원본 최대 **3MB** **(제안)**<br>- CloudFront로 캐싱하며, 도면 버전이 바뀌면 캐시를 무효화한다.<br>- 로딩 중에는 스켈레톤을 표시하고 실패 시 재시도 버튼을 제공한다. | M |
| MAP-002 | 확대·이동 | 핀치 줌과 드래그 이동을 지원한다.<br>- **줌 범위 1배 ~ 4배** **(제안)**. 그 이상은 도면 해상도를 넘어 뭉개진다.<br>- 도면 경계를 벗어나 빈 공간이 보이지 않도록 이동을 제한한다.<br>- 더블 탭으로 2배 확대, 다시 더블 탭으로 원복 **(제안)**<br>- 줌·이동 중에도 마커가 함께 변환되어야 하며 프레임이 끊기지 않아야 한다. | M |
| MAP-003 | 마커 표시 | 부스·푸드트럭·편의시설을 도면 위에 표시한다.<br>- 카테고리별로 아이콘과 색을 구분하되 **아이콘 형태로도 구분**되게 한다(색만으로 구분하지 않는다).<br>- 마커가 겹치면 확대 수준에 따라 묶어서 표시한다 **(제안)**<br>- 웨이팅 사용 부스는 마커에 **대기 팀 수 뱃지**를 함께 표시한다.<br>- 접수 마감 부스는 마커를 흐리게 처리한다. | M |
| MAP-004 | 카테고리 필터 | 원하는 종류만 골라 본다.<br>- **다중 선택**을 지원하며 기본은 전체 표시다.<br>- 필터 칩을 지도 상단에 가로 스크롤로 배치한다 **(제안)**<br>- 필터 상태는 화면을 벗어났다 돌아와도 유지한다 **(제안)**<br>- 편의시설(화장실·상황실·의무실)은 별도 그룹으로 묶어 빠르게 켜고 끌 수 있게 한다. | M |
| MAP-005 | 현재 위치 표시 | 도면 위에 내 위치를 표시한다.<br>- 카카오맵 SDK로 GPS 좌표를 취득한다. **좌표는 서버로 전송하지 않는다.**<br>- 위치 갱신 주기 **5초** **(제안)**<br>- GPS 정확도가 **50m를 넘으면 오차 원을 함께 표시**한다 **(제안)**. 정확하지 않은 위치를 정확한 척 보여주지 않는다.<br>- 위치 추적은 지도 화면에서만 동작하며 이탈 시 중단한다(배터리 소모). | M |
| MAP-006 | 좌표 변환 정의 | GPS 좌표를 도면 좌표로 변환한다.<br>- 도면과 실좌표를 잇는 **기준점을 최소 3점** 등록하고 어파인 변환 행렬을 계산한다.<br>- **변환 계산은 클라이언트에서 수행한다.** 위치가 바뀔 때마다 서버에 물으면 왕복 비용만 든다.<br>- 기준점이 3개 미만이면 `400 M001`, 세 점이 **일직선이면 `400 M002`** 로 등록을 거부한다(특이행렬이 되어 변환 불가).<br>- 기준점은 서로 **가능한 멀리 떨어뜨려** 잡는다. 가까이 모이면 오차가 증폭된다. | M |
| MAP-007 | 영역 이탈 처리 | 축제장 밖에서는 위치를 표시하지 않는다.<br>- 캠퍼스 경계(위경도 범위)를 벗어나면 위치 마커를 숨긴다.<br>- **"축제장 밖에 있습니다"** 안내를 표시한다.<br>- 억지로 도면 가장자리에 붙여 표시하지 않는다. 잘못된 위치는 없는 것보다 나쁘다. | M |
| MAP-008 | 권한 거부 대응 | 위치 권한이 없어도 지도가 정상 동작한다.<br>- 도면·마커·필터·상세 연결은 모두 그대로 작동한다.<br>- 위치 권한을 재요청하는 배너를 한 번만 표시하고 반복하지 않는다 **(제안)**<br>- 카카오맵 SDK 로드 실패 시에도 동일하게 처리한다(NFR-R-002). | M |
| MAP-009 | 마커 상세 연결 | 마커에서 부스 정보로 이어진다.<br>- 마커 탭 시 하단에 **요약 시트**를 띄운다(부스명·카테고리·대기 팀 수·운영시간).<br>- 시트에서 부스 상세 또는 웨이팅 등록으로 바로 이동한다.<br>- 시트가 떠 있는 동안에도 지도를 조작할 수 있어야 한다 **(제안)**. | M |
| MAP-010 | 좌표 등록 도구 | 관리자가 도면 위를 클릭해 좌표를 지정한다.<br>- 좌우 분할 화면으로 왼쪽에 도면, 오른쪽에 미배치 목록을 둔다 **(제안)**<br>- 클릭한 위치에 핀이 놓이고 드래그로 미세 조정할 수 있다.<br>- **전체 핀을 한 번에 저장**한다. 하나씩 저장하면 수십 번 왕복하게 된다.<br>- **도면을 교체하면 기존 좌표가 어긋난다.** 교체 시 좌표 재검수 경고를 표시한다. | M |
| MAP-011 | 도면 로딩 최적화 | 현장 네트워크에서도 지도가 뜬다.<br>- WebP 압축 및 품질 조정으로 **1MB 이하**를 목표로 한다 **(제안)**<br>- 필요 시 확대 수준별 해상도를 분리해 제공한다.<br>- 도면은 CDN에서만 받고 API 서버를 경유하지 않는다. | S |

### 4.6 ADM — 관리자

| ID | 요구사항 | 설명 | 우선순위 |
|---|---|---|---|
| ADM-001 | 관리자 로그인 | 운영자가 ID·비밀번호로 로그인한다.<br>- 인증 성공 시 **Redis 기반 세션 쿠키**를 발급한다(`HttpOnly; Secure; SameSite=Lax`).<br>- **세션 유효 시간 8시간** **(제안)** — 축제 하루 운영을 덮는 길이다.<br>- **5회 연속 실패 시 10분 계정 잠금** **(제안)**. 무차별 대입을 막는다.<br>- 실패 사유를 구분하지 않고 "아이디 또는 비밀번호가 올바르지 않습니다"로 통일한다. 계정 존재 여부를 노출하지 않기 위함이다.<br>- 비밀번호는 BCrypt로 해싱해 저장한다. 평문 저장·로그 출력을 금지한다. | M |
| ADM-002 | 권한 분리 | 총괄 운영자와 부스 운영자의 접근 범위를 나눈다.<br>- **총괄 운영자:** 전체 리소스<br>- **부스 운영자:** 담당 부스의 대기 조회·호출·입장·노쇼·접수 상태만<br>- **검사는 서버에서 강제한다.** 프론트 메뉴 숨김은 통제가 아니다(NFR-S-002).<br>- 담당하지 않는 부스 접근 시 `403 A003`으로 거부하고 감사 로그에 남긴다.<br>- 한 계정이 여러 부스를 담당할 수 있다(푸드트럭 총괄 등). | M |
| ADM-003 | 호출 화면 | 부스 운영자용 대기 호출 콘솔을 제공한다.<br>- **다음 팀 호출 버튼을 화면에서 가장 크게** 배치한다.<br>- 대기 목록에 대기 번호·인원 수·대기 경과 시간·문자 발송 상태를 표시한다.<br>- 호출된 팀은 상단에 고정하고 **노쇼 후보를 강조**한다.<br>- **실수 방지:** 입장·노쇼 처리는 확인 없이 즉시 실행하되 **10초 이내 되돌리기**를 제공한다 **(제안)**. 확인 다이얼로그는 바쁜 현장에서 오히려 오조작을 늘린다.<br>- 태블릿 가로 화면에서 스크롤 없이 대기 5팀 이상이 보여야 한다 **(제안)**. | M |
| ADM-004 | 혼잡도 입력 화면 | 구역별 혼잡도를 빠르게 입력한다.<br>- 구역을 카드로 나열하고 각 카드에 4단계 버튼을 배치한다.<br>- **마지막 입력 후 경과 시간**을 카드에 표시하고, 권장 주기를 넘으면 강조한다.<br>- 추정 인원은 ±50 증감 버튼으로 조정한다.<br>- 저장은 버튼 한 번으로 끝나며 확인 절차를 두지 않는다. | M |
| ADM-005 | 긴급 공지 발행 | 전 이용자에게 즉시 공지를 전파한다.<br>- 제목·본문을 입력하고 긴급 여부를 지정한다.<br>- **긴급 공지는 발행 즉시 브로드캐스트**되며 전 화면 상단 배너로 노출된다.<br>- 게시 해제도 즉시 반영된다.<br>- 발행·해제를 감사 로그에 기록한다.<br>- 2단계에서는 발행 시 영문 번역을 우선 처리한다(I18N-009). | M |
| ADM-006 | 콘텐츠 관리 | 축제 정보를 등록·수정·삭제한다.<br>- 대상: 무대·구역, 공연·라인업, 부스·푸드트럭, 편의시설<br>- **삭제는 논리 삭제**를 기본으로 한다. 축제 당일 실수로 지워도 이력이 끊기지 않아야 한다.<br>- 이미지는 업로드 후 URL로 참조하며, 업로드 최대 **5MB** **(제안)**<br>- 필수 항목 누락 시 저장을 막고 어떤 항목이 비었는지 표시한다. | M |
| ADM-007 | QR 관리 | 부스 QR을 발급하고 인쇄용으로 내려받는다.<br>- 개별 QR은 PNG로, **전체 일괄은 PDF**로 제공한다.<br>- 인쇄물에는 **부스명과 "QR을 스캔해 줄을 서세요" 안내 문구**를 함께 넣는다 **(제안)**<br>- 재발급은 확인 절차를 거치며 기존 QR을 즉시 무효화한다.<br>- 발급 이력을 감사 로그에 남긴다. | M |
| ADM-008 | 실시간 현황판 | 총괄 운영자가 전체 상황을 한 화면에서 본다.<br>- 표시 항목: 부스별 대기 팀 수, 구역별 혼잡도, 현재 접속자 수, 오늘 등록·입장·노쇼 수, **문자 발송 현황과 잔여 한도**<br>- **2초 스로틀**로 갱신한다 **(제안)**. 호출이 잦은 시간대에 초당 수십 회 갱신되면 오히려 읽기 어렵다.<br>- 대기가 급증한 부스와 갱신이 밀린 구역을 강조한다.<br>- 접속자 수는 WebSocket 연결 수를 기준으로 집계한다. | M |
| ADM-009 | 조작 이력 | 누가 무엇을 했는지 기록한다.<br>- 기록 대상: 혼잡도 입력, 웨이팅 호출·입장·노쇼, 공지 발행·해제, 입장 통제 전환, 계정 관리, QR 발급, 개인정보 파기<br>- 각 기록에 수행자·시각·대상·IP를 남긴다.<br>- **축제 종료 후 90일 보관** **(제안)**<br>- 조회 시 페이지네이션을 적용한다(건수가 수천 건에 이른다). | M |
| ADM-010 | 데이터 내보내기 | 사후 분석용 원자료를 CSV로 받는다.<br>- 대상: 웨이팅 이력, 혼잡도 이력<br>- **UTF-8 BOM을 붙인다** **(제안)**. 없으면 Excel에서 한글이 깨진다.<br>- 기간을 지정해 내려받을 수 있다.<br>- **개인정보(전화번호)는 내보내기에 포함하지 않는다.** 분석에 필요 없고 유출 경로만 늘린다. | M |
| ADM-011 | 태블릿 최적화 | Admin Web을 현장 기기에 맞춘다.<br>- 기준 해상도 **1024×768 이상(가로)** **(제안)**<br>- 호출 콘솔은 **한 손 조작**이 가능하도록 주요 버튼을 화면 하단에 배치한다 **(제안)**<br>- 다크 배경을 쓰지 않는다. 야외 직사광에서 판독이 어렵다.<br>- 세로 모드에서도 깨지지 않되 최적화 대상은 아니다. | M |
| ADM-012 | 데이터 파기 | 축제 종료 후 개인정보를 지운다.<br>- 파기 대상: **전화번호**(축제 종료 후 7일 이내), 접속 로그 IP·익명 토큰(30일 이내)<br>- 실행 시 **확인 문구 입력**을 요구한다. 되돌릴 수 없는 작업이다.<br>- 파기 건수·시각·수행자를 기록으로 남긴다. 15주차 산출물의 증빙이 된다.<br>- 통계용 데이터는 개인 식별자를 제거한 상태로 유지한다. | M |

### 4.7 I18N — 외국어(영어) 지원 — 2단계

| ID | 요구사항 | 설명 | 우선순위 |
|---|---|---|---|
| I18N-001 | 언어 전환 | 한국어와 영어를 오간다.<br>- 전환 버튼을 헤더 또는 설정 화면에 둔다.<br>- 선택한 언어를 브라우저에 저장해 재방문 시 유지한다 **(제안)**<br>- 전환 시 화면을 새로 고치지 않고 즉시 반영한다. | M |
| I18N-002 | 브라우저 언어 감지 | 첫 진입 시 기본 언어를 자동으로 정한다.<br>- `Accept-Language` 또는 `navigator.language`가 `ko`로 시작하면 한국어, 그 외는 영어 **(제안)**<br>- 사용자가 한 번이라도 수동 전환하면 이후에는 자동 감지를 적용하지 않는다. | S |
| I18N-003 | UI 리소스 분리 | 고정 문구를 코드에서 분리한다.<br>- 모든 화면 문구를 한/영 리소스 파일로 관리한다.<br>- **코드에 한글 문자열을 직접 쓰지 않는다.** 나중에 찾아내기가 매우 어렵다.<br>- 번역 누락 시 키를 그대로 노출하지 않고 한국어로 폴백한다 **(제안)**. | M |
| I18N-004 | 콘텐츠 자동 번역 | 관리자가 등록한 텍스트를 영어로 제공한다.<br>- 대상: 부스명, 부스 소개, 공연명, 출연진, 공지 제목·본문, 편의시설명<br>- 번역 API를 **서버에서만** 호출한다. API 키를 클라이언트에 노출하지 않는다.<br>- **번역 대상에 개인정보가 포함되지 않는다.** | M |
| I18N-005 | 번역 캐싱 | 같은 문장을 반복 번역하지 않는다.<br>- **원문 SHA-256 해시를 키**로 캐싱한다.<br>- 조회 순서: Redis → DB → 번역 API<br>- Redis TTL **7일** **(제안)**, DB는 영구 보관<br>- 원문이 바뀌면 해시가 달라져 자연히 재번역된다. | M |
| I18N-006 | 실패 폴백 | 번역이 실패해도 서비스가 멈추지 않는다.<br>- 번역 API 타임아웃 **3초** **(제안)**<br>- 실패·타임아웃 시 **원문을 그대로 노출**하고 `FAILED`로 기록한다.<br>- **절대 500 오류로 이어지지 않는다**(NFR-R-002).<br>- 실패 목록을 관리자 화면에서 확인하고 재시도할 수 있다. | M |
| I18N-007 | 수동 오버라이드 | 오역된 고유명사를 직접 고친다.<br>- 총괄 운영자가 번역문을 수정하면 **수동 수정 표시**가 설정된다.<br>- **수동 수정된 항목은 자동 재번역 대상에서 제외**한다. 운영진이 고친 것을 자동 번역이 덮으면 안 된다.<br>- 학과명·동아리명처럼 오역이 잦은 항목을 우선 검수한다. | M |
| I18N-008 | 로케일 포맷 | 날짜·시간을 언어에 맞게 표시한다.<br>- 한국어: `10월 15일 (수) 20:00`<br>- 영어: `Wed, Oct 15, 8:00 PM` **(제안)**<br>- 시간대는 항상 KST를 기준으로 하며 현지 시각으로 변환하지 않는다. | S |
| I18N-009 | 긴급 공지 번역 | 안전 공지가 영어 이용자에게 늦지 않게 간다.<br>- 공지 발행 시 **번역을 우선순위로 처리**한다.<br>- 번역이 지연되면 **원문(한국어)이라도 먼저 노출**한다. 늦게 정확한 것보다 빨리 알리는 것이 중요하다.<br>- 번역 완료 시 화면을 갱신한다. | S |

## 8. 제약사항 및 가정

### 8.1 제약사항
- 축제 현장은 인파 밀집으로 모바일 네트워크 품질이 저하될 수 있다. 모든 화면은 저대역폭에서도 동작해야 한다.
- 부스 운영자 교육 시간이 제한적이므로 Admin Web은 설명 없이 사용 가능한 수준의 단순함을 유지한다.
- 개발 기간은 16주이며, 11주차 축제 현장 적용이 고정 마감이다.

### 8.2 가정
- 총학생회로부터 부스 목록·배치도·타임테이블을 축제 2주 전까지 확보할 수 있다.
- 축제용 캠퍼스 도면(부스 배치 반영)을 이미지 형태로 확보할 수 있다.
- 각 부스 운영자는 웨이팅 호출에 사용할 스마트폰 또는 태블릿을 보유한다.
- 부스별 QR 코드 인쇄·부착은 총학생회와 협력하여 수행한다.

### 8.3 위험

| 위험 | 영향 | 대응 |
|---|---|---|
| 호출 알림이 웹 화면 표시뿐이라 이용자가 호출을 인지하지 못함 | 노쇼 증가, 만족도 저하 | 대기표 화면 상시 유지 안내, 브라우저 알림 권한 유도, 호출 후 유예 시간 확보 |
| 전화번호 미입력자가 대기표를 잃음 (브라우저 데이터 삭제·기기 변경) | 이용자가 순서를 잃음 | 등록 화면에 대기 번호 크게 표시 + 캡처 유도, 운영자가 번호로 조회 (WAI-018) |
| **문자 발송 비용 초과** (자비 부담) | 팀 금전적 손실 | 일일 한도·건당 1회 제한(WAI-021), 한도 초과 시 화면 표시로 자동 전환, 실시간 비용 집계(WAI-022) |
| 문자 발송 사업자 장애 | 호출 알림 미도달 | 발송 실패를 기록하고 화면 표시는 계속 동작. 운영자가 재발송(WAI-020) |
| 도면-실좌표 정합 오차 | 현재 위치 오표시 | 기준점 다수 확보 및 현장 사전 실측 |
| 자동 번역의 고유명사 오역 | 유학생 혼란 | I18N-007 수동 오버라이드로 주요 명칭 사전 교정 |
| 현장 네트워크 장애 | 서비스 이용 불가 | 캐시 기반 조회 유지, 오프라인 안내 문구 |
| 부스 데이터 확보 지연 | 개발 일정 지연 | 더미 데이터로 선개발, 축제 직전 실데이터 주입 |

## 12. 제안값 목록 (확인 필요)

구현은 이 값으로 시작하되 **모두 설정 상수로 분리**해, 확정 후 코드를 고치지 않고 바꿀 수 있게 한다.
