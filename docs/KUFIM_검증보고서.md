## 0. 왜 이 검증을 했는가

이 시점에는 코드가 한 줄도 없다. 그렇다고 검증할 게 없는 것은 아니다.

- 요구사항에 있는데 기능 정의서에 빠진 항목
- 문서가 주장하는 개수와 실제 개수의 불일치
- DDL 구문 오류, FK 위반, enum 오타
- 어파인 변환처럼 **설계 단계에서 수학적으로 성립하는지 확인 가능한 것**
- 명도 대비처럼 **계산으로 결론이 나는 접근성 요건**

이런 결함은 지금 고치면 문서 한 줄이지만, 6주차에 발견하면 스키마와 화면을 동시에 갈아야 한다.

**주의**: 이 검증은 실제 MySQL 인스턴스나 실행 중인 서버를 대상으로 하지 않았다. 한계는 §8에 정리했다.

## 3. 업무 규칙 검증 (40건)

DB 제약으로 표현할 수 없는 규칙을 시드 데이터에 대해 검사했다.

| 그룹 | 검사 항목 | 결과 |
|---|---|---|
| **enum 값** | 13개 컬럼의 값이 문서 정의 집합에 속하는가 | 13/13 통과 |
| **다형 참조** | `map_pin → booth/facility` 존재, 핀 누락 부스·시설 | 4/4 통과 |
| **웨이팅 상태 정합성** | `called_at`/`closed_at` 유무가 상태와 일치, 시각 역전, 중복 활성 대기, `party_size` 범위, `waiting_seq` 정합 | 12/12 통과 |
| **이력 정합성** | 최초 이벤트 존재, 최종 이벤트 == 현재 상태, 허용된 상태 전이만 사용, ADMIN 이벤트의 `actor_id` | 4/4 통과 |
| **혼잡도** | `latest_congestion_log_id`가 같은 구역·실제 최신을 가리키는가 | 4/4 통과 |
| **공연 시간** | `end > start`, 축제 기간 내, 동일 무대 시간 겹침 | 3/3 통과 |
| **좌표** | 기준점 3점 이상·비일직선, 핀·기준점이 도면 범위 내 | 4/4 통과 |
| **권한·공지** | BOOTH_ADMIN 담당 부스 존재, `called_by`가 담당자인가, 발행 공지의 `published_at` | 4/4 통과 |

**상태 전이 검사**가 특히 유효했다. 허용 집합을 `{null→WAITING, WAITING→CALLED, WAITING→CANCELED, CALLED→ENTERED, CALLED→NO_SHOW}`로 두고 대조했으며, 시드 13건 전부가 이 집합 안에 있다. 기능 정의서 §4.1 상태 머신과 시드 데이터가 어긋나지 않음을 확인했다.

## 4. 좌표 변환 (MAP-006)

기준점 3쌍으로 어파인 변환 행렬을 실제로 풀었다.

| 검사 | 결과 |
|---|---|
| 계수행렬 행렬식 | `5.435e-06` — 비특이. 변환 성립 |
| 기준점 재투영 최대 오차 | `1.52e-08 px` — 사실상 0 |
| 도출된 축척 | 가로 6.17 px/m · 세로 5.23 px/m |
| 도면이 표현하는 실제 범위 | 약 **332 m × 294 m** |
| 가로/세로 축척비 | 1.179 (왜곡 허용 범위) |

> 시드의 기준점은 개발용 예시값인데도 **대학 캠퍼스 규모로 타당한 축척**이 나왔다.
> 즉 `MapCalibration` 3점 방식이 설계로서 성립하며, `M001`(3점 미만)·`M002`(일직선) 검증도 실제로 판정 가능함을 확인했다.
> 실제 도면 확보 후에는 기준점을 현장 실측으로 다시 잡아야 한다.

### 6.2 TypeScript 타입 생성 및 컴파일

`openapi-typescript`로 `kufim-api.d.ts`를 생성하고 `tsc --strict`로 검증했다.

**양성 테스트** — 정상 사용 코드 컴파일 통과
```ts
const allStatuses: WaitingStatusEnum[] = ["WAITING","CALLED","ENTERED","CANCELED","NO_SHOW"];
const req: WaitingCreateRequest = { partySize: 4 };   // 인원 수만으로 성립
```

**음성 테스트** — 잘못된 사용이 실제로 컴파일 오류를 내는지 확인

| 코드 | 결과 |
|---|---|
| `const bad: CongestionLevel = "UNKNOWN"` | 오류 — 4개 리터럴에 할당 불가 |
| `{ partySize: 4, phoneNumber: "010-..." }` | 오류 — `phoneNumber` 속성 없음 |
| `{ partySize: 4, privacyConsent: true }` | 오류 — `privacyConsent` 속성 없음 |
| `adminItem.phoneNumberMasked` | 오류 — 속성 없음 |

> `@ts-expect-error` 로 4건 모두 실제 오류임을 확인했다.
> **개인정보 미수집 결정(2026-09-01)이 타입 수준에서 강제된다.** 실수로 전화번호를 담는 요청을 만들면 컴파일이 실패한다.

전화번호가 있었다면 조회 수단이 되었을 것이다.

다만 **완화일 뿐 해소가 아니며**, 총학생회 인터뷰에서 현장 대응 방식을 확인해 운영 매뉴얼에 반영해야 한다.

## 11. 2026-09-01 2차 재검증 (문자 발송 · Redis 세션 반영)

같은 날 결정이 두 번 바뀌었다. 개인정보 미수집으로 갔다가, 계획서의 문자 발송을 살리기로 하면서 **전화번호 선택 수집**으로 재확정했다.
동시에 관리자 인증을 JWT → Redis 세션으로 변경했다. 전 항목을 다시 돌렸다.

| 검사 | 결과 |
|---|---|
| DDL 구문 파싱 | 통과 (테이블 20개) |
| 스키마·시드 적재, FK 검사 | 통과. `sms_send_log` 5건 포함, 위반 0 |
| 업무 규칙 40건 | 통과 |
| 좌표 변환 | 통과 |
| 문서 교차 정합성 10축 | 통과 (기능 86 · 에러 코드 28 · 엔드포인트 80) |
| 디자인 토큰 접근성 | 통과 |
| OpenAPI 3.1 | 통과 (operation 80, schema 58) |
| TypeScript 타입 | 통과 + 음성 2/2 검출 |

### 변경 요약

| 대상 | 변경 |
|---|---|
| `waiting` | `phone_number`(선택), `privacy_consent` 복귀 + `idx_waiting_phone` |
| **`sms_send_log`** | 신설. 발송 결과·비용 기록. **전화번호는 저장하지 않음** |
| Redis 키 | `sms:sent:{waitingId}`, `sms:daily:{date}`, 관리자 세션 추가 (11종) |
| 관리자 인증 | JWT → Spring Session + Redis. `/admin/auth/refresh` 제거, `force-logout` 신설 |
| API | `resend-sms`, `sms/usage` 신설. 에러 `C002`·`W010`·`W011` 추가 (28종) |
| 요구사항 | WAI-019~022, NFR-S-008 신설 |
| 기능 | F-WAI-21~24 신설 → 86개 |

### 타입 음성 테스트

| 코드 | 결과 |
|---|---|
| `LoginResponse.accessToken` | 오류 — 세션 전환으로 제거됨 |
| `paths["/admin/auth/refresh"]` | 오류 — 경로 없음 |

`{ partySize: 4 }` (번호 없이)와 `{ partySize, phoneNumber, privacyConsent }` 는 모두 정상 컴파일된다. **선택 입력이 타입에 정확히 반영되었다.**

### 자비 부담에 대한 안전장치

발송 비용을 팀이 부담하므로 비용 통제를 설계에 넣었다.

| 장치 | 위치 |
|---|---|
| 웨이팅 1건당 호출 문자 1회 | Redis `sms:sent:{waitingId}` |
| 일일 발송 한도 | Redis `sms:daily:{date}` |
| 한도 초과 시 문자만 중단, 화면 표시는 유지 | `SKIPPED_LIMIT` 기록 |
| 재발송은 운영자만 | `POST /admin/waitings/{id}/resend-sms` |
| 실시간 비용 집계 | `GET /admin/sms/usage` |

> **한도를 넘어도 웨이팅 기능은 멈추지 않는다.** 이 설계 덕분에 예산이 소진돼도 서비스가 살아 있다.
> 다만 **일일 한도 숫자 자체가 아직 미정**이다(TBD-07). 예산 상한을 정해야 산정할 수 있다.
